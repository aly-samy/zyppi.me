## 2. Executive Verdict

**DISPOSITION A — READY TO PIN** (with supplementary verification gaps recorded in §18).

This research directly verified, from authoritative GS1 sources, all core standards-pinning facts required by the mandate:

- The normative authority for GS1 Digital Link URI syntax is the **GS1 Digital Link Standard: URI Syntax, Release 1.6.0, Ratified, Mar 2025**, published by GS1 AISBL at `ref.gs1.org/standards/digital-link/uri-syntax/` [[1]].
- The governing AI/identifier/validation authority is the **GS1 General Specifications Standard, Release 26.0, Ratified, Jan 2026** [[10]][[107]].
- The authoritative AI registry is the **GS1 Application Identifiers registry at `ref.gs1.org/ai/`**, dynamically maintained with a machine-readable JSON-LD dataset [[19]][[244]].
- Rules for AI `01`, `10`, `17`, and `21` were verified, including formats, character sets, regular expressions, FNC1 requirements, and Digital Link category roles [[88]][[189]][[199]].
- Source status and update models, and snapshot methods for reproducing the baseline, were established.

No fact in this report establishes that Zyppi is GS1-certified, GS1-qualified, or formally GS1-conformant. This report provides decision inputs only; it does not make Zyppi architectural decisions.

## 6. GS1 Digital Link URI Syntax Authority

- **Exact official title:** "GS1 Digital Link Standard: URI Syntax" [[1]].
- **Issuing authority:** GS1 AISBL (GS1) [[1]].
- **Canonical publication location:** `https://ref.gs1.org/standards/digital-link/uri-syntax/`; GS1 states that the official versions of all GS1 standards are provided as PDF files on `https://ref.gs1.org` [[170]].
- **Edition/version:** Release 1.6.0; Document Version 1.6, Issue 0 [[1]].
- **Publication date:** Mar 2025 per the document summary table on the official page and per the GS1 standards posting log ("Mar 2025, GS1 Digital Link Standard: URI Syntax, Release 1.6") [[1]][[17]]. Note: the GS1 public overview page displays "URI syntax 1.6.0 (Apr 2025)" [[2]]; see §18 gap G-04.
- **Status:** Ratified [[1]].
- **Normative status:** Normative. Its core is expressed in ABNF grammar (RFC 5234) in section 4 "such that conformance can be determined with certainty" [[1]].
- **Maintenance model:** Revised periodically under the GS1 Standards Management Process; releases are logged in the posting log [[17]]; an archive of prior versions exists at `ref.gs1.org/standards/digital-link/archive` [[36]].
- **Supersession:** The URI Syntax document supersedes the corresponding portion of the original "all in one" GS1 Digital Link Standard (first ratified August 2018), which is now a legacy document whose current version was published January 2026 with no further updates expected [[32]][[2]].
- **Family position:** GS1 states "The term 'GS1 Digital Link' should be seen as synonymous with this standard," and it is "the foundation on which all other aspects of the standard are built" [[32]].
- **Exact citation:** _GS1 Digital Link Standard: URI Syntax, Release 1.6.0, Ratified, Mar 2025, GS1 AISBL, https://ref.gs1.org/standards/digital-link/uri-syntax/_.

**Version-conflict note (derived):** A GS1 US-hosted PDF copy of the General Specifications displays "Release 25.0" [[117]], while the authoritative GS1 global pages state 26.0 (Jan 2026) [[10]][[107]][[17]]. The 25.0 PDF is treated as a stale cached copy, not the current edition (§18, gap G-05).

## 8. GS1 Application Identifier Registry Authority

- **Authoritative source:** GS1 Application Identifiers registry at `https://ref.gs1.org/ai/` [[19]].
- **Maintenance model:** Dynamically maintained. The registry is a tool for viewing/searching AI details, and "the current dataset for this tool is available in JSON-LD" [[19]][[244]]. The registry itself directs users to the GS1 General Specifications for full AI details [[19]].
- **Versioning:** The registry does not carry a standalone edition number; it reflects the current AI assignments maintained under the GS1 standards process, with authoritative backing from the current GS1 General Specifications (Release 26.0) [[19]][[10]].

- **Registry index entries verified (title/data title):** AI 01 = Global Trade Item Number (GTIN), data title "GTIN"; AI 10 = Batch or lot number, data title "BATCH/LOT"; AI 17 = Expiration date (YYMMDD), data title "USE BY or EXPIRY"; AI 21 = Serial number, data title "SERIAL" [[19]].

## 9. Verified Rules for AI 01, AI 10, AI 17, and AI 21

### AI 01 — GTIN

- **Official title:** Global Trade Item Number (GTIN); data title "GTIN" [[19]].
- **Category:** Primary identification key. In a GS1 Digital Link URI, AI 01 is a primary key that may be qualified by CPV (AI 22), batch/lot (AI 10), and serial number (AI 21) [[55]].
- **Format:** 14 digits in the Digital Link context: "gtin-value = 14DIGIT" [[1]]. GTIN-8/12/13 values are prefixed with leading zeroes to reach 14 digits [[1]].
- **Check digit:** Required. "The last digit of all fixed-length, numeric GS1 Identification Keys is a check digit that ensures the integrity of the key. All GS1 ID Keys need a check digit, except Component/Part Identifier (CPID) and Global Individual Asset Identifier (GIAI)" [[181]]. The exact modulo-10 algorithm statement resides in the General Specifications; this research verified its existence and location but did not quote the algorithm text (§18, gap G-01).

### AI 10 — Batch or Lot Number

- **Official title:** Batch or lot number; data title "BATCH/LOT" [[19]].
- **Category:** Key qualifier for GTIN in GS1 Digital Link [[55]].
- **Format:** "N2+X..20" (2-digit AI plus variable-length value, up to 20 characters) [[189]].
- **Character set:** Regular expression `([!%-?A-Z_a-z\x22]{1,20})` [[189]] — this corresponds to the GS1 alphanumeric character set used for X-format element strings.
- **FNC1 required:** Yes (element-string context) [[189]].
- **Digital Link placement:** Key qualifier → path element (see §10).

### AI 17 — Expiration Date

- **Official title:** Expiration date (YYMMDD); data title "USE BY or EXPIRY" [[19]].
- **Category:** Data attribute (a date attribute carried in the query string in GS1 Digital Link) [[19]][[1]].
- **Format:** "N2+N6" — 2-digit AI plus 6-digit date in YYMMDD form [[88]].
- **Regular expression:** `(\d{2}(?:0\d|1[0-2])(?:[0-2]\d|3[01]))` — two-digit year; month 01–12; day 00–31 [[88]].
- **FNC1 required:** No [[88]].
- **Day value 00:** The registry regex admits day `00`. GS1 change notification GSCN 21-040 states "the representation of a day as '00' is NOT valid for regulated healthcare products" [[230]], indicating day `00` has context-dependent validity. The current General Specifications' definitive statement for general vs healthcare use was not quoted (§18, gap G-02).
- **Year interpretation / leap-year behavior:** Not quoted from the normative text in this research; the regex constrains ranges but calendar validation specifics remain an open verification item (§18, gap G-02).

### AI 21 — Serial Number

- **Official title:** Serial number; data title "SERIAL" [[19]].
- **Category:** Key qualifier for GTIN in GS1 Digital Link; GTIN + serial number together identify a product instance [[55]].
- **Format:** "N2+X..20" (variable length, up to 20 characters) [[199]].
- **Character set:** Regular expression `([!%-?A-Z_a-z\x22]{1,20})` [[199]].
- **FNC1 required:** Yes [[199]].
- **Digital Link placement:** Key qualifier → path element, ordered after CPV/batch-lot per §10.

## 10. Digital Link URI Structure and AI Placement

All findings below are from the normative text of the GS1 Digital Link Standard: URI Syntax (Release 1.6.0) as published at `ref.gs1.org`:

- **Identifiers in the path:** Yes. "The URI path information is the most appropriate place for expressing a GS1 identification key and an ordered set of optional qualifiers... to form a compound key" [[1]].
- **Exactly one primary key in the path:** "In any GS1 Digital Link URI there SHALL be exactly one primary key, followed by any key qualifiers relevant to that primary key as path elements" [[1]]. Where more than one primary key must be encoded, one SHALL be in the path and the rest encoded in the query string as data attributes [[1]].
- **Data attributes in the query string:** "The query string is appropriate for data attributes of the identified resource such as expiry date, weight etc., as well as being a natural extension point for any additional arbitrary key=value pairs that cannot be expressed using GS1 Application Identifiers" [[1]].
- **Path ordering is fixed:** For GTIN, the qualifier sequence is significant: "/01/{gtin}/22/{cpv}/10/{lot}/21/{serial}"; components may be omitted but "the sequence in which they appear is important and must be preserved" [[1]]. The Resolver Standard states the same ordering: GTIN (or ITIP), CPV, batch/lot, serial number [[55]].
- **Path-vs-query equivalence:** Not universal. The path carries the identification key and its qualifiers (identity); the query string carries data attributes and extension parameters, and "does not form part of the entity's identifier" [[55]]. Semantic equivalence between path and query placement is therefore not asserted by the standard; each AI has an assigned position by category (Directly verified).
- **Custom domains and URI stems:** Permitted. "A company chooses to use their own registered Internet domain name... zero or more path segments are permitted to appear after the hostname or domain name and before the start of the gs1uriPattern" [[1]]. The Resolver Standard confirms the domain name is not used for entity identification [[55]].
- **Repeated parameters / unknown parameters / fragments:** No normative disposition rule was located in the authoritative sources reviewed for repeated query parameters or URI fragments; unknown non-GS1 query parameters are explicitly permitted as extension pairs [[1]], but required handling is left to implementations (see §14).

## 11. Canonicalization and Equivalence Findings

The GS1 Digital Link Standard: URI Syntax defines a **canonical GS1 Digital Link URI** (section 4.12), with classifications per mandate §4.5:

| Rule                                                                                              | Classification                                                                                  |
| ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Canonical URI scheme SHALL be HTTPS                                                               | Explicitly required by GS1 normative text [[1]]                                                 |
| Canonical URI domain name SHALL be `id.gs1.org`                                                   | Explicitly required by GS1 normative text [[1]]                                                 |
| Deprecated convenience string equivalents for AIs SHALL NOT be used                               | Explicitly prohibited by GS1 normative text [[1]]                                               |
| GTIN-8/12/13 SHALL remain padded to 14 digits                                                     | Explicitly required by GS1 normative text [[1]]                                                 |
| Canonical URI query string SHALL NOT contain key=value pairs other than GS1 AIs                   | Explicitly required by GS1 normative text [[1]]                                                 |
| Query key=value pairs "should be sorted in lexical, not numeric, order of the key"                | Explicitly stated with "should" (not SHALL) by GS1 normative text [[1]]                         |
| Percent-encoding of reserved characters (#, /, %, &, +, comma, !, (, ), \*, ', :, ;, <, =, >, ?)  | Defined by GS1 normative text incorporating RFC 3986 §2.1 [[1]]                                 |
| "Canonical URI" concept                                                                           | Defined by another cited standard incorporated by GS1 (RFC 6596 cited in §4.12) [[1]]           |
| Scheme case, host case, trailing-slash equivalence, percent-encoding case, decode/re-encode rules | Not found as explicit GS1 normalization rules in the sources reviewed (see resolver note below) |

Important context: the canonical form is defined for contexts "e.g., to support carriers that cannot embed a Web URI"; in general, "A GS1 Digital Link URI can be constructed in any domain name" and that flexibility "is a deliberate feature of the standard" [[1]]. Therefore the canonical `id.gs1.org` form and any-domain form are different constructs with different intended uses (Directly verified).

**Resolver-side equivalence findings (GS1-Conformant Resolver Standard 1.2.0):** trailing slashes are "not conformant to the GS1 Digital Link syntax... however, it is likely to be common and therefore resolvers SHOULD be tolerant of it" [[55]]. Duplicate AIs: "If duplicate AI found, check values are the same" (recommended basic validation) [[55]]. These are resolver-behavior rules, not URI-syntax canonicalization rules.

**Not found:** A GS1-mandated general-purpose normalization/equivalence algorithm for arbitrary GS1 Digital Link URIs (e.g., host-case folding, scheme-case folding) in the sources reviewed. Any Zyppi normalization beyond the explicit rules above is an application-level decision (see §20).

## 12. GTIN Representation and Check-Digit Findings

- **14-digit representation in Digital Link:** "As of version 1.4.0, the GS1 Digital Link standard: URI syntax now expects the GTIN value to be expressed using 14 digits... the value of a GTIN-8, GTIN-12 or GTIN-13 SHALL be prefixed with leading zeroes serving as filler digits to reach a total of 14 digits, exactly as explained in section 2.1.1.10 of the GS1 General Specifications" (Directly verified) [[1]].
- **ABNF binding:** "gtin-value = 14DIGIT" [[1]].
- **Check digit:** Required for GTIN; "The last digit of all fixed-length, numeric GS1 Identification Keys is a check digit that ensures the integrity of the key"; all GS1 ID Keys need a check digit except CPID and GIAI; GMN uses check-character pairs [[181]].
- **Algorithm location:** The General Specifications contain the "Check digit and calendar date algorithms" [[180]]; the exact modulo-10 procedure was not quoted (§18, gap G-01).
- **Distinctions preserved (per mandate §4.6):** (a) a _valid GTIN value_ is one satisfying length, digit-only, and check-digit rules under the General Specifications [[181]]; (b) a _valid GTIN serialized in a Digital Link_ is its 14-digit zero-padded form in the path [[1]]; (c) a _canonicalized GTIN representation_ appears in the canonical URI (HTTPS, `id.gs1.org`, padded to 14 digits) [[1]]; (d) a _syntactically valid URI containing an invalid GTIN_ is possible — the resolver distinguishes invalid GS1 Digital Link URIs (HTTP 400) from valid-but-unknown identifiers (HTTP 404) [[55]].

## 13. Date and Character-Set Validation Findings

- **AI 17 date format:** YYMMDD, format N2+N6, regex `(\d{2}(?:0\d|1[0-2])(?:[0-2]\d|3[01]))`, data title "USE BY or EXPIRY" [[88]].
- **Day `00`:** Admitted by the registry regex [[88]]; explicitly stated as NOT valid for regulated healthcare products per GSCN 21-040 [[230]]. Current General Specifications' definitive day-00 rule for general use not quoted (§18, gap G-02).
- **ISO 8601:** No evidence was found that GS1 AI 17 adopts ISO 8601; the governing format is YYMMDD as defined by GS1 (Derived from [[88]]; absence of ISO reference noted, not conclusive).
- **AI 10 / AI 21 character sets:** Both use the same GS1 X-format character set, regex `([!%-?A-Z_a-z\x22]{1,20})`, variable length 1–20 [[189]][[199]]. Case is significant (the regex distinguishes character classes; no normalization rule was found). Leading zeros are data characters (no rule found declaring them insignificant). Whitespace is not within the published regex character set. Empty values are not permitted by the `{1,20}` quantifier. Neither AI carries a check digit (no check-digit requirement is published for them [[189]][[199]]).
- **Element string vs Digital Link representation:** The same AI formats apply; in the Digital Link URI, characters with special URI meaning must be percent-encoded per the standard's character-set table [[1]].

## 14. Unknown and Unsupported AI Findings

- **Unknown/unsupported AIs:** No implementation-disposition rule (reject/preserve/ignore/forward) was found in the GS1 Digital Link Standard: URI Syntax governing how an implementation must treat a valid-but-unsupported AI, an AI unknown to an implementation, or a future AI added after an implementation's snapshot. **No implementation-disposition rule was found in the authoritative GS1 sources reviewed.**
- **Resolver guidance (adjacent, informative):** The GS1-Conformant Resolver Standard recommends designing validation "in such a way that they allow for new AIs that are not defined at the time the resolver was built," and classifies "AIs are known, as new AIs are introduced" among the more fast-changing checks implementations MAY perform [[55]]. This is resolver guidance, not a mandated disposition for arbitrary parsers.
- **Invalid-position or format-violating AIs:** The resolver standard requires differentiation between a request URI that fails syntactic validity tests (HTTP 400) and one that is valid but unknown to the resolver (HTTP 404) [[55]]. The URI Syntax standard's ABNF defines the well-formedness boundary [[1]].
- **Non-GS1 query parameters:** Explicitly permitted as extension key=value pairs [[1]]; the Resolver Standard states the query string "does not form part of the entity's identifier" and implementations "MAY make use of query string parameters but this standard does not define a particular behaviour" [[55]].
- **Conclusion:** Disposition of unsupported content is an application-level decision for Zyppi; GS1 defines the syntactic boundary and permits extension parameters but does not mandate a handling policy (Open question for the Zyppi Council, not a GS1 gap).

## 16. Certification, Qualification, and Conformance Findings

Answered separately per mandate §4.11:

1. **GS1 certification program specifically for a software URI parser:** **Not found.** No GS1 program certifying software URI parsers was verified in the sources reviewed.
2. **GS1 certification program specifically for a Digital Link resolver:** **Not found.** The GS1-Conformant Resolver Standard defines normative resolver requirements [[55]] and GS1 publishes a resolver test suite [[69]], but no GS1-operated resolver certification program was verified.
3. **GS1 qualification/conformance program applicable to Digital Link software:** Conformance is demonstrated via the official test suite [[69]] and the BSR [[127]]; no formal GS1 qualification program for Digital Link software was verified.
4. **GS1 certification for Digital Link barcodes/data carriers:** Exists in practice as data-carrier certification activity tied to Sunrise 2027 (e.g., 2D Digital Link barcode certification services evaluating "data validation, syntax compliance, print quality, and placement") [[66]], plus GS1 US test kits [[67]][[46]]. These certify **barcodes/data carriers and scanning capability**, not software parsers.
5. **GS1 partner program relevant to Digital Link implementation:** Yes — the GS1 US Solution Partner Program, "a network of member companies who are trusted strategic partners" with "education and certification" for partners [[118]][[123]]; "GS1-certified solution provider" language appears in GS1 US materials [[120]]. This is a **partner status**, not a software-conformance certification.
6. **Pre-deployment tests associated with GS1 Digital Link / Sunrise 2027:** Yes — GS1 US Sunrise 2027 test kits and sample 2D barcodes for scanning capability [[46]][[156]][[67]], and GS1's overall Sunrise 2027 initiative (2D barcode acceptance at retail POS by end of 2027) [[46]].
7. **What each program certifies:** Partner programs certify a business relationship; barcode/data-carrier certification certifies printed symbols and scanning; test suites provide self-assessment of conformance. None certifies that a third-party software parser is "GS1-certified."
8. **Evidence required before any claim:** Per mandate terminology, "GS1-certified" or "GS1-qualified" may only be claimed if an applicable GS1 program exists and its verification process is completed; no such program for software parsers/resolvers was verified. At present, Zyppi can target **standards-conformant** behavior demonstrated against traceable requirements and **conformance-testable** design via the official test suite and BSR [[69]][[127]].

## 19. Risks if Implementation Begins Before Pinning

1. **Superseded-edition risk:** Internal cross-references in current GS1 documents point at older General Specifications editions (V24.0, 23.0.0) [[1]][[55]], and stale PDFs circulate (25.0) [[117]]; implementing against an unverified edition risks building on obsolete AI definitions.
2. **GTIN representation drift:** The 14-digit zero-padding rule was introduced at URI Syntax 1.4.0 [[1]]; code written against pre-1.4 behavior would produce non-conformant identifiers.
3. **Incorrect AI category handling:** Confusing key qualifiers (path) with data attributes (query) produces structurally invalid URIs; the path-order rule for GTIN qualifiers is fixed [[1]][[55]].
4. **Date-validation errors:** Misinterpreting AI 17 day-00 semantics or calendar rules produces incorrect expiry validation, with healthcare-specific restrictions already diverging from general rules [[230]].
5. **False certification claims:** Treating partner programs, barcode/data-carrier certification, or test suites as software certification would produce unsupported "GS1-certified" claims (§16).
6. **Unlicensed test material:** Importing GS1 test corpora without confirming licenses creates legal exposure (gap G-07).

## 24. Appendix C — Source Access and Availability Notes

- **Primary canonical location:** All official GS1 standard versions are published as PDFs on `ref.gs1.org` [[170]]; this is the recommended citation and archival base.
- **Access method used:** Public web pages were retrieved on the research date; no GS1 login, membership, or paid service was required for any cited standard landing page or registry entry.
- **Retrieval anomaly:** Individual AI registry pages (`ref.gs1.org/ai/01`, `/10`, `/21`) returned 404 responses to the automated retrieval tool while the same official content is indexed and quotable [[88]][[189]][[199]]; this is recorded as gap G-06 and should be re-checked manually at pinning time.
- **Stale copies in circulation:** The GS1 US-hosted General Specifications PDF displays Release 25.0 [[117]], and current GS1 standards internally cite older GenSpecs editions (V24.0 in URI Syntax [[1]]; 23.0.0 in Resolver [[55]]). Only GenSpecs 26.0 (Jan 2026) is current [[10]][[107]][[17]].
- **Machine-readable assets:** The AI registry offers a JSON-LD dataset for snapshotting [[244]]; the GS1 Barcode Syntax Dictionary is a plain-text file of all assigned AIs [[127]]; both are suitable for reproducible baselines once exact URLs are captured (gap G-03).
- **Licensing:** The BSR is "freely licensed open source" [[130]]; exact license text for the Resolver Test Suite and BSR must be read in their GitHub repositories before any repository inclusion (gap G-07).
- **Update cadence:** The General Specifications follow an approximately annual cycle (26.0 Jan 2026; next planned Jan 2027) [[10]]; the posting log tracks all releases including errata [[17]]; the AI registry is maintained dynamically [[19]]. Any pinned baseline should record its access date and a re-verification trigger.
