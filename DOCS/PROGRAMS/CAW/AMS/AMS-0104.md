## Objective

Configure a root-level **ESLint v9 Flat Config** that provides consistent TypeScript linting across the monorepo and mechanically enforces the import boundaries already defined in CAW-004.

## Scope

Implement only the ESLint tooling required for the current repository skeleton.

The implementation SHALL:

1. Use **ESLint v9 Flat Config** with a root-level:

```text
eslint.config.mjs
```

1. Configure linting for all TypeScript source files under:

```text
apps/**
packages/**
edge/**
```

1. Exclude generated and dependency directories, including:

```text
node_modules/
dist/
build/
coverage/
*.d.ts
```

1. Use the current compatible TypeScript ESLint tooling.
2. Add a root lint command compatible with the existing monorepo scripts:

```bash
pnpm lint
```

1. Enforce the CAW-004 architectural boundaries at the import level.

At minimum, the configuration SHALL reject:

- Any import from `apps/*` or `edge/*` into `packages/runtime`.
- Any import from `apps/*`, `edge/*`, or higher-layer Zyppi packages into `packages/domain`.
- Any direct import from `packages/runtime` into `apps/web`.
- Any other workspace import explicitly prohibited by the CAW-004 ownership and import rules.

1. Allow legitimate imports within the same package and legitimate dependencies explicitly permitted by CAW-004.
2. Provide clear lint errors identifying the prohibited architectural relationship.

## Out of Scope

Do **not**:

- Implement runtime-purity enforcement beyond import-path boundaries.
- Add AST-based checks for forbidden Node, network, database, filesystem, or Cloudflare APIs.
- Inspect or enforce `package.json` dependency purity.
- Implement the dedicated Runtime Purity CI Gate.
- Modify TypeScript project-reference configuration.
- Configure Prettier.
- Add application logic, domain models, runtime logic, or production source code.
- Introduce repository-wide style rules unrelated to this task.

The deeper constitutional purity checks belong to **IT-0108**, not this mandate.

## Inputs

The authoritative dependency and ownership rules are defined by:

```text
CAW-004 — Ownership / Import Rules
```

The existing TypeScript project-reference graph created by IT-0103 SHALL remain unchanged.

## Constraints

- Use **ESLint v9 Flat Config**. Do not create `.eslintrc`, `.eslintrc.json`, `.eslintrc.js`, or any legacy ESLint configuration.
- Do not weaken or alter CAW-004 boundaries to make linting easier.
- Do not duplicate TypeScript dependency rules that are already enforced by project references unless ESLint is required to provide a clearer import-level failure.
- Keep the configuration minimal and maintainable.
- Use only dependencies necessary for this task.
- Do not add custom plugins or custom AST rules unless the required CAW-004 boundaries cannot be expressed through stable, maintained ESLint tooling.
- The implementation SHALL work from the repository root through the standard pnpm command.

## Acceptance Criteria

All of the following SHALL be true:

1. ESLint v9 is installed and the repository uses root-level Flat Config.
2. The following command succeeds with zero lint errors on the current repository:

```bash
pnpm lint
```

1. The configuration recognizes and lints TypeScript files across:

```text
apps/
packages/
edge/
```

1. A temporary forbidden import from `packages/runtime` to an `apps/*` or `edge/*` module causes `pnpm lint` to fail.
2. A temporary forbidden cross-layer import into `packages/domain` causes `pnpm lint` to fail.
3. A temporary direct import from `packages/runtime` into `apps/web` causes `pnpm lint` to fail.
4. The temporary verification imports are removed before completion.
5. No legacy ESLint configuration files are introduced.
6. The existing TypeScript project-reference configuration remains unchanged and `pnpm exec tsc -b` continues to succeed.

## Required Verification

Run:

```bash
pnpm lint
pnpm exec tsc -b
```

Both commands SHALL complete successfully after all temporary boundary-test changes have been removed.

Perform the required negative tests by temporarily introducing prohibited imports, confirming that ESLint rejects them, and then restoring the repository to a clean state.

## Definition of Done

- Root-level `eslint.config.mjs` exists and uses ESLint v9 Flat Config.
- `pnpm lint` succeeds on the repository.
- CAW-004 import boundaries covered by this mandate are mechanically enforced.
- Required negative boundary tests have been performed successfully.
- `pnpm exec tsc -b` still succeeds.
- No legacy ESLint configuration exists.
- No application or runtime logic has been added.
- No work belonging to IT-0105 through IT-0108 has been implemented.
- Changes are committed with a clear task-linked commit message.
