## 3. Constitutional Basis

CAW-007 defines `ExecutionReceipt` as an **immutable, per-execution** Runtime artifact containing:

1. Receipt ID;
2. Execution ID;
3. Runtime Version;
4. Input Hash;
5. Output Hash;
6. Evidence Hash;
7. Policy Version;
8. Decision Summary;
9. Execution Time;
10. Deterministic Hash.

CAW-007 further requires:

> Same input → same receipt → same hash, always.

This task establishes the Domain representation required to carry those values.

The following distinction is mandatory:

- **IT-0310 defines the receipt model.**
- **IT-0405 generates receipts.**
- **M12 performs deterministic replay verification.**

Do not implement behavior belonging to IT-0405, M12, or any future Runtime task.

## 6. Required Field Rules

### 6.1 String fields

The following fields must each be a primitive string that is neither empty nor whitespace-only:

- `receiptId`
- `executionId`
- `runtimeVersion`
- `inputHash`
- `outputHash`
- `evidenceHash`
- `policyVersion`
- `decisionSummary`
- `deterministicHash`

Whitespace-only values must be rejected using the established M03 validation convention.

Validation must not modify or trim the original value.

No additional grammar is authorized.

Do not require:

- UUID syntax;
- Semantic Version syntax;
- hexadecimal syntax;
- Base64 syntax;
- fixed hash lengths;
- cryptographic algorithm prefixes;
- structured decision-summary syntax.

Those formats are not defined by the governing sources for this M03 task.

### 6.2 `executionTime`

`executionTime` must:

- be a primitive JavaScript `number`;
- be finite;
- be greater than or equal to `0`;
- reject `NaN`;
- reject `Infinity`;
- reject `-Infinity`;
- reject negative values;
- reject strings, booleans, `null`, and other non-number values.

The unit and measurement mechanism remain intentionally unspecified.

Do not assume:

- milliseconds;
- nanoseconds;
- CPU time;
- wall-clock duration;
- monotonic-clock duration.

Do not read a clock or calculate duration.

`executionTime` is an explicit recorded value supplied to the Domain model.
