- # AMS-0301 — Identity Domain Model

  **Implements: IT-0301 · Milestone: M03 · Size: S · Depends On: IT-0202 (☑) · Status: ☐ Planned**

  ## Load

  CEngS-000, CEngS-001 §4, CEngS-002 §4, CAW-000, **CAW-003** (this task's actual specification — read the Identity row, the Rules section, and the Cross-Entity Consistency note).

  ## Objective

  Implement the `Identity` domain model in `packages/domain` as a pure, immutable, serializable TypeScript type — the persistent digital representation resolved from a Digital Link, per CAW-003.

  ## Grounding (why this shape, not a citation exercise)

  Per ZRM-002 §5.1 and WS-03A.2 (already synthesized into CAW-003 — no need to re-derive): Identity is a **structural construct relating a Primitive's uniqueness to a Representation**. It is not the thing itself. `Identity ≠ Referent` is the one distinction that must never blur — the Identity is the record; the Referent (a future task, IT-0302 territory... actually Referent isn't separately numbered, it's folded into GS1/IT-0302, check CAW-003's table) is what it points to.

  ## Scope
  - `IdentityRecord` type (or equivalent name — see Naming below): the fields required to represent a commissioned Identity per CAW-003's Identity row.
  - Minimum fields, derived directly from CAW-003 + CAW-008's `identities` table (already specified — reuse it, don't invent new shape):
    - `identityId: string` (per the naming convention CAW-003 now specifies — not `id`)
    - `identityType: string`
    - `canonicalReference: string` (the Digital Link / GTIN it resolves from)
    - `referentId: string | null` (nullable — CAW-008 allows an Identity to exist before a Referent in Draft/Pre-Commissioned state, per WS-03A.2 §12, though this wedge's lifecycle is simplified — see Lifecycle below)
    - `status: 'draft' | 'active' | 'decommissioned'` (matches CAW-008's status column — don't invent additional states beyond what the schema already supports)
    - `createdAt`, `updatedAt` — but see Determinism note below on how these actually enter the type
  - Pure validation function(s): given raw input, return either a valid `IdentityRecord` or a typed validation error — no throwing, no exceptions as control flow (align with whatever error-handling convention CEngS-002/CEngS-001 §7 established — check before inventing a new one).
  - Canonical serialization support (RI-001) — the type must serialize deterministically; write the test that proves it, don't just assert it.

  ## Determinism Note (this is where domain-layer tasks most often quietly break CEngS-001 §4)

  `createdAt`/`updatedAt` are timestamps, but this is a **pure domain package** — it must never call `Date.now()` or `new Date()` internally. Timestamps are **inputs** to the validation/construction function, supplied by whatever layer calls it (ultimately the Application layer, which gets them from the Execution Context per CAW-007). If you find yourself wanting to default a timestamp inside `packages/domain`, stop — that's the Application layer's job, not Domain's.

  ## Naming

  Use `IdentityRecord` (not bare `Identity`) if there's any chance of collision with a built-in or a later `Identity` namespace/module — check CAW-003's other entities for a precedent before deciding; if none exists yet, this task sets the precedent other entities (IT-0302–0307) will follow, so choose deliberately and note the choice in the PR for the next task to reuse.

  ## Out of Scope

  Referent/GS1 model (IT-0302), any Runtime logic that _uses_ Identity (M04+), persistence/repository implementation (M05, already scaffolded structurally in CAW-008 but not implemented), any policy or authority logic referencing Identity (IT-0304+, and even then only the minimal wedge scope CAW-003 already defined — not the full delegation chain explicitly rejected in CAW-003's last section).

  ## Constraints
  - Zero imports beyond `packages/shared` if truly needed for a generic utility (e.g., a branded-type helper) — per CAW-004's leaf-package rule, `packages/domain` imports nothing by default; only use `shared` if there's a real, immediate need, not speculatively.
  - No I/O, no `Date.now()`, no `Math.random()`, no environment access — same rule as everywhere else in this stack, no exception for "it's just a domain type."
  - Every exported type/function has a corresponding test.

  ## Acceptance Criteria
  - `IdentityRecord` type exists, matches the fields above (or an explicitly justified variation — report any deviation from CAW-003/CAW-008's shape rather than silently diverging)
  - Validation function rejects malformed input with typed errors, accepts well-formed input
  - Canonical serialization round-trips correctly (serialize → deserialize → identical value) — this is the actual test, not just "it compiles"
  - No timestamp or randomness is generated inside `packages/domain` — verify this is also caught by AMS-0108's determinism checks if they apply this broadly, or note if they're currently `packages/runtime`-scoped only and this is a gap worth flagging for IT-0208's graph validator to eventually extend
  - `pnpm graph:validate`, `pnpm boundary:all` (if applicable to `domain`), `tsc -b`, `lint`, `test` all pass

  - Type, validator, and tests exist and pass
  - Naming convention documented for reuse by IT-0302–0307
  - PR reviewed against CL-001
  - CAW-011 IT-0301 marked ☑
