# AMS-0203 — Create `packages/contracts`

**Implements:** IT-0203
**Milestone:** M02 — Constitutional Package Structure
**Size:** XS
**Depends On:** IT-0108 ☑, AMS-0201 merged
**Status:** ☐ Planned

## Load

CEngS-000, CEngS-001, CEngS-002, CAW-000, CAW-004, CAW-006, and **AMS-0201**.

This mandate reuses the package-boundary pattern established by AMS-0201. Do not reproduce, redesign, duplicate, or weaken that infrastructure.

## Objective

Establish `@zyppi/contracts` as an independently buildable, publicly resolvable workspace package with a minimal ESM public boundary.

This task establishes package structure only. It does **not** implement API contracts, request models, response models, OpenAPI schemas, DTOs, validation, serialization, or Runtime behavior.

## Package Role and Authorized Boundary

Per CAW-004:

- `packages/contracts` is the shared contract boundary for API requests and responses.
- `packages/contracts` may import from `packages/domain`.
- `packages/contracts` must never import Runtime internals.

The authorized TypeScript project-reference boundary is established during M02. Actual Domain imports and contract definitions remain Just-in-Time and SHALL be introduced only by the mandate that implements them.

A TypeScript project reference is a compile-time boundary declaration. It is not equivalent to a production dependency declaration in `package.json`.

## Apply the AMS-0201 Package Pattern

Create or normalize the following package structure:

```text
packages/contracts/
├── package.json
├── src/
│   └── index.ts
└── tsconfig.json
```

### 1. Package Manifest

`packages/contracts/package.json` SHALL follow the established workspace package pattern:

```json
{
  "name": "@zyppi/contracts",
  "version": "<canonical repository version>",
  "private": true,
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsc -b",
    "verify": "node ../../tools/verify-package-boundary.mjs --package=packages/contracts"
  },
  "dependencies": {},
  "peerDependencies": {}
}
```

Use the repository’s existing canonical workspace version. Do not invent or independently increment a package version.

The production dependency baseline is explicitly Default-Deny:

- `"dependencies"` SHALL exist and equal exactly `{}`.
- `"peerDependencies"` SHALL exist and equal exactly `{}`.
- Do not add `@zyppi/domain` to `dependencies` during M02.
- Do not add external production or peer dependencies.

The future authorization to import Domain does not itself authorize a production package dependency before actual implementation requires one.

### 2. Public Entry Point

`packages/contracts/src/index.ts` SHALL contain exactly:

```ts
export {};
```

Do not add:

- API request types;
- API response types;
- OpenAPI types or schemas;
- DTOs;
- placeholder interfaces;
- empty namespaces;
- constants;
- comments;
- temporary exports;
- functionality intended only to make the package appear non-empty.

Contract definitions belong to their governing implementation milestone, not to M02 package scaffolding.

### 3. TypeScript Project Reference

`packages/contracts/tsconfig.json` SHALL preserve or establish the authorized compile-time reference:

```json
{
  "references": [{ "path": "../domain" }]
}
```

Do not add references to Runtime, Shared, Testing, applications, Edge, or any other package.

Do not remove the Domain reference merely because M02 contains no actual Domain imports. The reference encodes the constitutionally authorized compile-time boundary; actual imports remain deferred until required.

If the current repository project-reference graph conflicts with this requirement, stop and report the exact conflict rather than silently changing the architecture.

## Shared Boundary Verification

Reuse the generic verifier created by AMS-0201:

```bash
node tools/verify-package-boundary.mjs --package=packages/contracts
```

Do not:

- create a second package-boundary verifier;
- copy the verifier into `packages/contracts`;
- modify the shared verifier for package-specific policy;
- hardcode Contracts-specific rules into the verifier.

The shared verifier remains structural and manifest-driven. It verifies the package’s declared public boundary and dependency baseline; it does not replace the repository’s TypeScript project graph or enforce package-specific reference policy.

## Root Integration

Add the following root script to `package.json`:

```json
"contracts:boundary": "node tools/verify-package-boundary.mjs --package=packages/contracts"
```

Do not modify the root `ci` script as part of this XS package-scaffolding mandate unless the repository already has an established, canonical convention requiring every new package-boundary command to be added there.

The Contracts boundary command remains a required verification step for this mandate regardless of whether it is aggregated into the root CI script.

## Out of Scope

Do not implement:

- API endpoints;
- HTTP handling;
- API request or response types;
- OpenAPI schemas;
- DTOs;
- validation logic;
- Runtime contracts;
- Domain entities;
- contract serialization;
- contract tests with invented behavior;
- external dependencies;
- Runtime imports;
- application imports;
- Edge imports;
- any M03 or later functionality.

## Acceptance Criteria

- `packages/contracts` is recognized as the `@zyppi/contracts` workspace package.
- The package is independently buildable through `tsc -b`.
- The package exposes an explicit ESM public boundary through `main`, `types`, and `exports`.
- `src/index.ts` contains exactly `export {};`.
- `dependencies` and `peerDependencies` are explicitly present and exactly `{}`.
- The package has no production or peer dependencies.
- `tsconfig.json` contains only the authorized `../domain` project reference.
- No actual Domain import is introduced.
- No Runtime, Shared, Testing, application, Edge, or infrastructure reference is introduced.
- The generic package-boundary verifier passes against `packages/contracts`.
- Native Node package self-resolution succeeds through the declared public package boundary.
- The root `contracts:boundary` command succeeds.
- No contract behavior or premature API model is introduced.
