## AMS-0207 — Create `apps/web`

**Work Item:** IT-0207

**Milestone:** M02 — Repository Topology & Workspace Boundaries

**Status:** Ready for execution

**Classification:** Application scaffold / Experience-layer topology only

### 1. Objective

Create `apps/web` as a minimal, private, independently compilable ESM application workspace.

This mandate establishes the **identity, location, and topological boundary** of Zyppi’s future web Experience Layer. It does **not** implement the web application, install Next.js, establish rendering behavior, or introduce frontend runtime configuration.

The governing principle is:

> **M02 establishes topology, not behavior.**

`apps/web` is an application execution target, not a reusable workspace library. It SHALL therefore be structurally distinct from `packages/*`.

---

## 2. Required Final Structure

After implementation, the application SHALL have the following structure:

```text

apps/web/

├── package.json

├── tsconfig.json

└── src/

    └── main.ts

```

`apps/web/src/main.ts` SHALL be the only source file introduced by this mandate.

---

## 3. Application Manifest

Create or update:

```text

apps/web/package.json

```

The manifest SHALL:

- Use the canonical repository version:

```json

"version": "0.1.0"

```

- Define the application identity:

```json

"name": "@zyppi/web"

```

- Declare the application as private:

```json

"private": true

```

- Declare native ESM:

```json

"type": "module"

```

- Provide the application build command:

```json

"scripts": {

  "build": "tsc -b"

}

```

- Declare explicit empty production and peer dependency baselines:

```json

"dependencies": {},

"peerDependencies": {}

```

The manifest SHALL NOT include:

- `main`

- `types`

- `exports`

- Next.js

- React

- Vite

- any frontend framework

- any browser runtime dependency

- any speculative workspace dependency

- any dependency not required by the current M02 scaffold

The application is not a publishable library and SHALL not expose a library-style public package surface.

---

## 4. Source Boundary

Remove any pre-existing placeholder source files that are not part of the required final structure.

Create:

```text

apps/web/src/main.ts

```

Its contents SHALL be exactly:

```ts
export {};
```

Do not add:

- application initialization

- startup functions

- framework bootstrapping

- React components

- Next.js configuration

- routes

- pages

- layouts

- browser APIs

- DOM access

- logging

- environment access

- side effects

- comments

- placeholder functions

- temporary exports

`export {};` is an inert TypeScript module marker for the M02 application scaffold. It does not represent a functional application entry lifecycle and SHALL not be expanded during this mandate.

---

## 5. TypeScript Configuration

Update:

```text

apps/web/tsconfig.json

```

The configuration SHALL:

- Preserve the established repository TypeScript base configuration.

- Preserve the existing compiler settings where they remain valid for the empty M02 application scaffold.

- Preserve the existing source inclusion configuration.

- Explicitly declare:

```json

"references": []

```

The application SHALL have **zero TypeScript project references** during AMS-0207.

Do not add references to:

- `packages/runtime`

- `packages/domain`

- `packages/contracts`

- `packages/shared`

- `packages/testing`

- `apps/api`

- any other workspace

Authorization for future consumption is not the same as a current dependency. No project reference SHALL be declared until a later ratified mandate introduces an actual, authorized import requirement.

Do not create:

- `tsconfig.base.web.json`

- a browser-specific TypeScript base configuration

- DOM library settings

- JSX compiler settings

- bundler-specific module resolution

- Next.js TypeScript configuration

- framework-specific compiler options

- a special TypeScript exception or duplicate configuration hierarchy

The existing repository TypeScript configuration SHALL remain the M02 baseline unless it produces a demonstrated present compilation failure.

A foreseeable future framework requirement is not, by itself, a present architectural defect.

---

## 6. Framework and Rendering Deferral

CAW-004 identifies Next.js as the ratified future web framework. That architectural identity does **not** authorize installation or implementation during M02.

AMS-0207 SHALL NOT:

- install Next.js

- install React

- create a Next.js application

- create `app/` or `pages/`

- create layouts or components

- configure routing

- configure SSR

- configure CSR

- configure static generation

- configure hydration

- configure caching

- configure browser runtime behavior

- introduce frontend build tooling

The web rendering strategy remains deferred to the future mandate that authorizes actual Experience-layer implementation.

---

## 7. Boundary Verification and Root Integration

`apps/web` is an application execution target, not a workspace library.

Therefore, AMS-0207 SHALL NOT:

- add a `web:boundary` command

- run `apps/web` through `tools/verify-package-boundary.mjs`

- modify the shared package-boundary verifier

- invent application-specific boundary-verification semantics

- introduce custom web validation tooling

Application-specific dependency and execution-boundary enforcement SHALL be addressed by the appropriate later governance work, including IT-0208 where applicable.

The root `ci` script SHALL remain **completely unchanged**.

Do not add web-specific commands to the root CI chain.

The required M02 integration is successful participation in the repository’s existing workspace processes, including installation, formatting, linting, TypeScript compilation, testing, and applicable repository validation.

---

## 8. Dependency Baseline

The final dependency posture SHALL be:

```json

"dependencies": {},

"peerDependencies": {}

```

No dependency may be added merely because it is expected to be used in a future milestone.

The dependency graph SHALL represent **current architectural reality**, not anticipated implementation.
