# 1. Question Presented

The governing question for G-0808 is:

**What is the minimum explicit execution boundary required for M08 to satisfy the constitutional requirements for Execution Context, determinism, replayability, and absence of hidden state, while preserving a single authoritative source for constitutional state?**

The Council is not deciding whether an explicit execution context is required. That requirement is already established by the governing engineering corpus cited by the M08 mandate.

The Council is deciding **how the required execution dimensions are represented and bound within the M08 execution model.**

# 2. Authority and Evidence Basis

This decision is governed by, and shall not weaken:

1. Ratified Zyppi constitutional authorities;

2. Ratified CEngS requirements applicable to Runtime execution, determinism, replay, and hidden-state prohibition;

3. `RI-006`;

4. `CAW-007 — Runtime Contracts`;

5. `CAW-003 — Domain Model`;

6. `CAW-011 — Commerce Atlas Wedge Build Order`;

7. M08 preparation and gate records;

8. M08 repository reconnaissance;

9. Decisions of predecessor gates that are already ratified.

Where repository behavior differs from governing requirements, the repository behavior is evidence of the **current implementation state**, not authority.

The current repository representation is:
`ExecutionRequest {   requestId: string   identity: Identity   activeConstitutionalView: ActiveConstitutionalView   evidenceBundle: EvidenceBundle   policyContext: PolicyContext   executionContext: ExecutionContext } `
and:
`ExecutionContext {   budget: number   entropy: string   versions: readonly string[] } `
This structure is explicitly documented by `CAW-007` and confirmed by M08 reconnaissance.

The reconnaissance further establishes that the Runtime currently has no system-clock, `Math.random()`, `crypto.randomUUID()`, filesystem, network, or asynchronous completion-order dependency.

# 3. Constitutional Compliance Finding

The Council finds that the current `ExecutionContext` is **insufficient** for M08.

This is not because `budget`, `entropy`, or `versions[]` are inherently invalid.

It is because the current representation does not make the complete constitutional execution boundary sufficiently explicit.

The seven required conceptual dimensions are:

1. Execution Budget

2. Policy Snapshot

3. Authority Context

4. Capability Context

5. Evidence Context

6. Constitution Version

7. Execution Identifier

The current architecture already carries most of these concepts, but distributes them across `ExecutionRequest`, `ActiveConstitutionalView`, `EvidenceBundle`, `PolicyContext`, and `ExecutionContext`.

The Council therefore rejects the interpretation that compliance requires duplicating all seven dimensions as literal data fields inside `ExecutionContext`.

Instead, the Council adopts the following interpretation:

**"Execution Context" is the explicit constitutional boundary of an execution, not necessarily a single TypeScript object containing duplicated copies of every underlying state object.**

The complete `ExecutionRequest` is the execution-input aggregate.

`ExecutionContext` is the execution-boundary component within that aggregate.

# 4. Selected Architectural Direction

## D-0808-01 — Hybrid Explicit Context Binding

**DECISION: SELECTED**

M08 shall use a **Hybrid Explicit Context Binding** model.

Execution-specific values shall be represented directly.

Authoritative state already owned by another constitutional object shall remain owned by that object and shall be **explicitly bound by immutable identity/reference**, rather than duplicated.

Conceptually:
`ExecutionRequest │ ├── requestId ├── identity ├── ActiveConstitutionalView ───────┐ ├── EvidenceBundle ────────────────┤ ├── PolicyContext ─────────────────┤ └── ExecutionContext               │        │                           │        ├── executionId             │        ├── constitutionalTime      │        ├── budget                  │        ├── optional entropy        │        └── snapshot bindings ◄─────┘ `
The precise cryptographic representation of these bindings is deferred to G-0809.

# 5. Rejected Alternative — Literal Duplication

## D-0808-02

**DECISION: REJECTED**

The Council rejects the proposition that all seven constitutional dimensions must be copied literally into the `ExecutionContext` object.

### Reasons

This would:

- duplicate ACV state;

- create multiple representations of constitutional truth;

- create synchronization hazards;

- increase canonical serialization complexity;

- complicate hash-domain design;

- weaken the single-authority principle.

The `ExecutionContext` shall therefore **not become a second Active Constitutional View**.

The authoritative object remains the authoritative object.

# 6. Rejected Alternative — Unbound Distribution

## D-0808-03

**DECISION: REJECTED**

The Council also rejects a model in which the seven dimensions are merely distributed across `ExecutionRequest` with no explicit binding relationship.

The existing architecture already distributes state across:

- ACV;

- EvidenceBundle;

- PolicyContext;

- ExecutionContext.

The problem is not distribution itself.

The problem is the absence of an explicit, verifiable statement of **which exact snapshots participated in a particular execution**.

Therefore:

**Distributed ownership is permitted; unbound execution state is not.**

A deterministic completeness/binding predicate shall be established before Runtime admission.

# 7. Policy Snapshot Authority

## D-0808-04

**DECISION: SELECTED**

The authoritative source for the Runtime's policy-evaluation context shall remain the **`PolicyContext`**.

`ActiveConstitutionalView.applicablePolicies` shall not become a second independent policy snapshot.

Where ACV contains policy references or applicable-policy metadata, those references shall be interpreted as part of the ACV's constitutional state, while the policy evaluation snapshot remains owned by `PolicyContext`.

The exact policy snapshot semantics are deferred to G-0807.

# 8. Authority Context

## D-0808-05

**DECISION: SELECTED**

The authoritative source for Authority Context shall remain the **`ActiveConstitutionalView`**.

The Execution Context shall bind the relevant ACV snapshot rather than duplicate its Authority records.

# 9. Capability Context

## D-0808-06

**DECISION: SELECTED**

The authoritative source for Capability Context shall remain the **`ActiveConstitutionalView`**.

The Execution Context shall bind the relevant ACV snapshot rather than duplicate its Capability records.

# 10. Evidence Context

## D-0808-07

**DECISION: SELECTED**

The authoritative execution evidence shall remain the **`EvidenceBundle`** supplied explicitly to the Runtime.

The Runtime shall never retrieve evidence implicitly.

The existing architecture already follows this principle: the Application layer assembles the EvidenceBundle and passes it into the Runtime; the Runtime verifies what it receives and does not access storage itself.

The Execution Context shall therefore bind the evidence snapshot/bundle identity rather than duplicate its contents.

# 11. Constitution Version

## D-0808-08

**DECISION: SELECTED**

Constitution version shall be an **explicitly typed semantic value**, not an untyped member of:
`versions: readonly string[] `
The Council rejects `versions[]` as a constitutional representation because it cannot express which version belongs to which semantic authority.

The authoritative Constitution Version shall belong to the constitutional snapshot/ACV layer.

The execution boundary shall bind the exact constitutional snapshot/version participating in the execution.

The exact version-binding serialization and hash participation are deferred to G-0809.

# 12. Execution Identifier

## D-0808-09

**DECISION: REQUIRED**

`executionId` is a distinct constitutional execution identifier.

It shall not be treated as synonymous with `requestId`.

The Council adopts the semantic distinction:
`requestId     = external/application request identity  executionId     = identity of one constitutional Runtime execution `
A single request may theoretically result in multiple independently identifiable executions.

The exact generation, format, uniqueness, and provenance rules for `executionId` are delegated to **G-0814**.

G-0808 establishes **requirement and placement**, not generation mechanics.

# 13. Entropy

## D-0808-10

**DECISION: CONDITIONAL, EXPLICIT, GOVERNED**

The Council does **not** remove entropy from the constitutional model merely because the present M08 pipeline does not require uncontrolled randomness.

However, entropy shall **not be mandatory merely for the sake of having a value**.

The adopted rule is:

**If a governed Runtime operation requires randomness, a cryptographic nonce, or equivalent entropy, that entropy MUST enter explicitly through the execution boundary.**

If no governed operation requires entropy:
`entropy = absent `
shall be a valid deterministic execution state.

The Runtime MUST NOT obtain entropy implicitly from:

- operating-system entropy;

- `Math.random()`;

- cryptographic random generators;

- system clocks;

- environment variables;

- network state;

- filesystem state;

- thread scheduling.

If entropy is present and consumed by a governed operation, it becomes part of the identical-input set and must therefore participate in deterministic replay.

The precise entropy representation and hash-domain treatment are delegated to G-0809.

# 14. Constitutional Time

## D-0808-11

**DECISION: REQUIRED**

Where M08 constitutional logic requires temporal evaluation, time shall enter explicitly as an execution input.

The Runtime shall never obtain constitutional time from the host clock.

The execution boundary therefore reserves an explicit temporal input:
`constitutionalTimestamp `
The Council does **not** decide in G-0808:

- precision;

- timezone representation;

- canonical formatting;

- temporal validity rules;

- ordering semantics;

- clock-drift policy.

Those decisions belong to **G-0801**.

The current repository reconnaissance confirms that the Runtime currently contains no system-clock access and that temporal semantics remain an open architectural matter.

# 15. Runtime Version

## D-0808-12

**DECISION: NOT AN EXECUTION-CONTEXT DIMENSION**

`runtimeVersion` shall not be introduced into `ExecutionContext` merely to satisfy the seven constitutional dimensions.

Runtime version is an identity/provenance attribute of the Runtime implementation and is appropriately represented in execution receipts and implementation provenance.

The current receipt contract already contains `runtimeVersion`.

Whether runtime version participates in a particular hash domain is a **G-0809** question.

# 16. ACV Snapshot Identity

## D-0808-13

**DECISION: REQUIRED**

The Council determines that the `ActiveConstitutionalView` must possess an independently verifiable snapshot identity if it is to serve as the authoritative source for Authority Context, Capability Context, and constitutional state participating in an execution binding.

The current repository state does not yet provide standalone canonical serialization for ACV. Reconnaissance explicitly identifies ACV as canonically serialized only when nested within `ExecutionRequest`.

Therefore:

**An ACV snapshot identity is a required architectural capability before the Hybrid Explicit Context Binding model can be fully implemented.**

This does **not** authorize G-0808 to select the hash algorithm or final hash-domain construction.

That work belongs to G-0809.

# 17. ACV Standalone Canonical Serialization

## D-0808-14

**DECISION: REQUIRED CAPABILITY; SEMANTICS DEFERRED**

The ACV must be independently canonicalizable.

This is necessary because a binding such as:
`Execution → ACV-Snapshot-X `
is not independently verifiable unless Snapshot X possesses deterministic canonical identity.

The Council therefore requires a standalone ACV serialization capability.

The following remain outside G-0808:

- canonicalization algorithm selection;

- hash algorithm;

- hash-domain labels;

- concatenation/encoding rules;

- digest representation.

These are G-0809 decisions.

# 18. Identical Input Boundary

## D-0808-15

**DECISION: DEFINED AT SEMANTIC LEVEL**

For M08 replay purposes, two executions are considered to have identical constitutional inputs only when all constitutionally relevant explicit inputs and bindings are identical.

The semantic input boundary consists of:

### Direct execution inputs

- execution identifier, subject to the final replay identity rules;

- constitutional timestamp, where required;

- execution budget;

- entropy, if present;

- other explicitly admitted execution-control values subsequently ratified by the applicable gates.

### Bound authoritative state

- exact Active Constitutional View snapshot;

- exact Policy Context snapshot;

- exact Evidence Bundle snapshot;

- other explicitly admitted constitutional inputs.

### Explicitly excluded ambient state

- wall-clock time;

- operating-system randomness;

- environment variables;

- filesystem state;

- network state;

- latency;

- thread scheduling;

- locale;

- host timezone;

- process-global mutable state.

The final field-by-field enumeration of hash participation is delegated to G-0809.

This distinction is deliberate:

**Replay-input membership and hash-domain membership are related but are not assumed to be identical by G-0808.**

# 19. Completeness and Admission Rule

The Council establishes the following architectural requirement:

**An execution shall not enter the constitutional Runtime unless the complete execution boundary can be deterministically validated.**

The admission validation must establish that:

1. every required constitutional dimension is represented;

2. every required snapshot is present;

3. every binding identifies one exact snapshot;

4. no required value is supplied implicitly;

5. optional entropy is absent or explicitly supplied;

6. temporal input, where required, is explicit;

7. the execution identifier is present;

8. no conflicting duplicate source of truth exists.

The exact validation contract and failure codes may be defined in the appropriate implementation mandate after the remaining dependent gates close.

# 21. Final Contract Direction

The current:
`interface ExecutionContext {   readonly budget: number;   readonly entropy: string;   readonly versions: readonly string[]; } `
is therefore **not the final M08 contract**.

The Council directs the architecture toward a shape conceptually equivalent to:
`interface ExecutionContext {   readonly executionId: string;   readonly constitutionalTimestamp: string;   readonly budget: number;   readonly entropy?: string;    readonly constitutionalSnapshotBinding: SnapshotBinding;   readonly policySnapshotBinding: SnapshotBinding;   readonly evidenceSnapshotBinding: SnapshotBinding; } `
This is a **semantic direction, not an implementation specification**.

The exact names, types, binding representation, canonical serialization, and hash participation shall not be inferred from this illustrative structure.

In particular, the Council does **not** authorize an implementation agent to copy this interface verbatim.

# 22. What Is Rejected

The Council explicitly rejects:

### R1 — Duplicating ACV state inside ExecutionContext

Rejected because it creates multiple sources of constitutional truth.

### R2 — Leaving the seven dimensions merely distributed without bindings

Rejected because presence alone does not establish which exact snapshots participated in execution.

### R3 — Untyped `versions[]`

Rejected because semantic ownership cannot be determined mechanically.

### R4 — Ambient time

Rejected.

### R5 — Ambient randomness

Rejected.

### R6 — Making entropy mandatory for every execution

Rejected.

### R7 — Treating `requestId` as the execution identifier

Rejected.

### R8 — Treating `runtimeVersion` as one of the seven constitutional Execution Context dimensions

Rejected.

### R9 — Defining hash algorithms or hash domains in G-0808

Rejected as scope expansion; delegated to G-0809.

# 24. Closure Condition

**G-0808 shall remain OPEN at this stage.**

The Council has now selected the architectural direction:

**Hybrid Explicit Context Binding.**

However, the gate cannot be marked fully closed until the dependent semantic decisions and required supporting capabilities have been established.

The Council therefore records:

**Disposition: CONDITIONALLY DECIDED / REMAINS OPEN**

This is intentional.

Closing G-0808 now would convert an architectural direction into an implementation-ready contract while several load-bearing semantics remain unresolved.

# 25. Constitutional Principle Established

The Council records the following principle for future M08 decisions:

**The execution boundary shall bind authoritative state; it shall not duplicate authoritative state.**

And:

**Every constitutionally relevant input shall be explicit, attributable, and reproducible; no constitutional execution may depend upon ambient host state.**

These principles govern the subsequent design of the M08 Runtime without granting implementation authority by themselves.

## Council Determination

**G-0808 has resolved the architectural direction but has not yet satisfied its closure conditions.**

The Runtime shall not treat `ExecutionContext` as a container for duplicated constitutional state. It shall function as an explicit execution boundary whose execution-specific values are represented directly and whose authoritative external state is bound through deterministic, independently identifiable snapshots.

No implementation agent may infer final TypeScript shapes, serialization rules, identifier-generation rules, or cryptographic domains from this record alone.
