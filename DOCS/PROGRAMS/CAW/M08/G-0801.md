# 1. Purpose

This Council Decision Record resolves `G-0801 — Temporal Semantics`.

The gate determines the constitutional meaning of temporal input within deterministic Runtime execution.

It does **not** determine:

- receipt `executionTime` semantics;

- policy-evaluation algorithms;

- policy-version semantics;

- ACV selection algorithms;

- canonical serialization or cryptographic hash construction;

- implementation details beyond the semantic constraints established herein.

Those matters remain governed by their respective gates.

# 2. Governing Authority

This decision is made under the authority hierarchy established by `G-0805 — Normative Corpus Authority` and the applicable ratified constitutional corpus.

The decision also incorporates the execution-boundary determination established by `G-0808 — Execution Context Sufficiency`.

`G-0808` establishes that constitutional temporal input is an explicit execution input and that the Execution Context may contain literal execution-specific temporal data.

The M08-GDR identifies G-0801 as the gate responsible for resolving temporal semantics after the authority and execution-context foundations have been established.

# 3. Constitutional Question

The Council must determine whether temporal validity inside Zyppi Runtime execution is based upon:

1. an explicit temporal coordinate;

2. a logical or cryptographic execution sequence;

3. a hybrid model; or

4. another Council-approved model.

The fundamental requirement is that temporal evaluation must not introduce hidden environmental state into Runtime execution.

The Runtime must therefore never obtain constitutional time by observing its execution environment.

# 4. Decision

## Direction A — Explicit Constitutional Temporal Coordinate

The Council hereby adopts **Direction A**.

Zyppi constitutional temporal evaluation SHALL use an **explicit temporal coordinate supplied as part of the authorized execution input**.

The canonical semantic name for this coordinate is:

`constitutionalTimestamp`

The temporal coordinate represents the time against which constitutional temporal validity may be evaluated for the execution.

It is an **input to execution**, not an observation made by the Runtime.

Conceptually:
`ExecutionRequest       │       ▼ ExecutionContext       │       └── constitutionalTimestamp `
The precise structural placement and binding relationship shall conform to the already-established `G-0808` Execution Context decision.

# 5. Constitutional Meaning of `constitutionalTimestamp`

`constitutionalTimestamp` SHALL mean:

**The explicit temporal coordinate against which temporal applicability of constitutional material may be evaluated for a particular execution.**

It SHALL NOT mean:

- the wall-clock time at which the Runtime happens to execute;

- the process start time;

- the server time;

- the database time;

- the network time;

- the receipt creation time;

- an implicit "now";

- an implementation-generated timestamp.

The Runtime therefore has no constitutional authority to replace the supplied temporal coordinate with an ambient clock value.

# 6. Temporal Determinism

For any execution whose constitutional evaluation depends upon temporal validity, the temporal coordinate SHALL be an explicit member of the execution's authorized input.

Therefore:
`same explicit temporal coordinate + same remaining authorized inputs + same authorized constitutional state = same temporal evaluation `
A later replay SHALL NOT produce a different temporal result merely because the replay occurs at a different wall-clock time.

The passage of real-world time between the original execution and replay is therefore not itself an execution input.

# 7. Runtime Purity

The Runtime SHALL NOT obtain constitutional time from ambient infrastructure.

The following mechanisms are constitutionally prohibited as sources of execution time:
`Date.now() new Date() performance.now() system wall clock database server time network time process start time host time container time environment-provided current-time values `
The prohibition applies regardless of implementation language or runtime platform.

An implementation that reads ambient time and subsequently stores the result in an otherwise deterministic structure does not satisfy this decision.

The temporal value must enter the execution boundary explicitly.

# 8. Temporal Applicability

The existence of `constitutionalTimestamp` does not mean that every constitutional evaluation necessarily requires temporal comparison.

Temporal evaluation SHALL occur when the applicable constitutional material has a temporal validity requirement.

Where the applicable constitutional material has no temporal dependency, the mere presence of a temporal coordinate does not itself create a temporal policy requirement.

The determination of **which policies or constitutional material require temporal evaluation** belongs to the policy and constitutional evaluation semantics governed by the appropriate downstream gates, particularly `G-0807`.

`G-0801` establishes the temporal coordinate and its constitutional meaning; it does not define the policy-evaluation mechanism.

# 9. Historical Constitutional Evaluation

Where an execution concerns the constitutional validity of a decision at temporal coordinate `T`, the applicable constitutional state SHALL be evaluated with respect to that temporal coordinate.

This establishes the temporal principle:

**Historical interpretation is evaluated against the constitutional state applicable to the explicit temporal coordinate of the execution.**

This decision does not prescribe the mechanism by which the Runtime obtains or resolves:

- the applicable ACV;

- the applicable policy;

- the applicable policy version;

- the applicable authority set;

- or other historical constitutional state.

Those mechanisms belong to the relevant authority, policy, and execution-context decisions.

# 10. Why an Explicit Temporal Coordinate Is Selected

The Council selects Direction A because it satisfies the constitutional requirements with the least semantic distortion.

### 10.1 Determinism

Time becomes an explicit input rather than an environmental dependency.

### 10.2 Replayability

A historical execution can be reconstructed with the same temporal coordinate regardless of when replay occurs.

### 10.3 Auditability

The execution record can identify the temporal coordinate under which constitutional validity was evaluated.

### 10.4 Runtime Purity

The Runtime does not need access to a system clock or any external temporal service.

### 10.5 Semantic Accuracy

A temporal coordinate represents actual temporal position directly.

A sequence number does not inherently represent time. It would require an additional constitutional mapping between sequence and temporal meaning.

### 10.6 Minimality

The model adds one explicit constitutional input without introducing an independent temporal subsystem or a second temporal authority.

# 11. Rejected Directions

## Direction B — Cryptographic / Logical Sequence

**REJECTED.**

A sequence can provide ordering but does not intrinsically provide temporal meaning.

Using sequence as the constitutional temporal primitive would require additional rules defining:

- who assigns the sequence;

- how sequence values map to time;

- how historical time is recovered;

- how independent execution contexts compare temporally;

- how federated or distributed execution maintains temporal meaning.

Those additional semantics would increase constitutional complexity without being necessary to satisfy deterministic temporal evaluation.

A sequence may be useful for other constitutional purposes, but it is not adopted as the fundamental temporal coordinate by this gate.

## Direction C — Hybrid Temporal Model

**REJECTED as the constitutional base model.**

A hybrid system combining timestamp and sequence would create two potentially authoritative temporal representations.

Without a demonstrated requirement for two independent temporal primitives, that would introduce unnecessary ambiguity over:

- which coordinate governs temporal validity;

- whether timestamp or sequence takes precedence;

- how disagreement is resolved;

- which value participates in replay identity.

A future gate may introduce an additional sequencing primitive for a different semantic purpose, but that does not alter the temporal model established here.

## Direction D — Temporal Evaluation Deferred

**REJECTED.**

Deferring temporal semantics would leave executions involving temporally bounded constitutional material without a defined deterministic temporal coordinate.

The absence of a temporal implementation requirement does not justify leaving the constitutional meaning of time unresolved.

# 12. Representation Boundary

The Council deliberately does **not** prescribe the byte-level representation of `constitutionalTimestamp` in this gate.

This gate establishes its semantic role.

The representation SHALL subsequently be governed by the appropriate canonicalization and hashing decisions.

In particular, the eventual representation must provide:

- deterministic interpretation;

- unambiguous temporal meaning;

- stable canonical serialization;

- defined absence semantics;

- compatibility with the execution-input hash boundary where applicable.

No implementation may choose a representation merely because it is convenient or provided by a language/runtime default.

# 13. Precision Boundary

`G-0801` does not independently ratify a particular fractional precision, epoch encoding, byte encoding, or serialization syntax.

Those are representation and canonicalization questions.

Accordingly, the Council does **not** make "nanosecond precision" a standalone constitutional requirement in this gate.

If a downstream canonicalization or hashing decision requires a particular precision, that precision must be explicitly defined there and must remain semantically compatible with this decision.

The constitutional requirement established here is:

**The temporal coordinate must be explicit, deterministic, unambiguous, and reproducible.**

# 14. Relationship to `executionTime`

`constitutionalTimestamp` and receipt `executionTime` are distinct concepts.

`constitutionalTimestamp` answers:

**At what explicit temporal coordinate was constitutional validity evaluated?**

`executionTime` answers a separate receipt/output question:

**What temporal information, if any, should the execution receipt report about execution itself?**

`G-0801` therefore does not determine the semantics of `executionTime`.

That question remains with `G-0802`.

An implementation SHALL NOT assume that `constitutionalTimestamp` and `executionTime` are interchangeable merely because both may contain temporal values.

# 15. Relationship to G-0807

`G-0801` establishes the temporal coordinate.

`G-0807` determines the semantics by which applicable policies and constitutional material are evaluated.

Therefore:
`G-0801 Temporal coordinate       │       ▼ G-0807 Policy / constitutional temporal evaluation `
G-0801 does not decide:

- which policy is applicable;

- which policy version is selected;

- how temporal policy ranges are represented;

- how conflicting temporal policies are resolved.

Those remain outside this gate.

# 16. Relationship to G-0808

`G-0808` establishes the execution-context boundary.

G-0801 supplies the semantic rule governing the temporal member of that boundary.

The resulting constitutional model is:
`Explicit Execution Context         │         ├── execution budget         ├── policy binding         ├── authority binding         ├── capability binding         ├── evidence binding         ├── constitution binding         └── constitutionalTimestamp `
The exact complete composition of the Execution Context remains governed by `G-0808`.

# 17. Relationship to G-0809

The temporal coordinate may participate in constitutional hashing where the governing hash-domain decision requires it.

`G-0801` therefore establishes **semantic eligibility**, not cryptographic construction.

`G-0809` shall determine:

- whether `constitutionalTimestamp` enters a particular hash domain;

- its canonical serialization;

- encoding;

- ordering;

- domain separation;

- and other cryptographic construction rules.

No implementation may infer those rules from G-0801.

# 18. Constitutional Invariants

The following invariants are established by this decision:

### T-0801-01 — Explicit Temporal Input

Constitutional temporal evaluation SHALL use an explicit temporal coordinate.

### T-0801-02 — No Ambient Time

The Runtime SHALL NOT read environmental or system time for constitutional evaluation.

### T-0801-03 — Deterministic Temporal Evaluation

Identical authorized inputs and identical constitutional state SHALL produce identical temporal evaluation regardless of replay time.

### T-0801-04 — Temporal Coordinate Identity

`constitutionalTimestamp` SHALL represent the temporal coordinate of constitutional evaluation and SHALL NOT be silently reinterpreted as generic execution time.

### T-0801-05 — Historical Evaluation

Temporal constitutional evaluation SHALL be relative to the explicit temporal coordinate supplied for the execution.

### T-0801-06 — No Sequence Substitution

A logical or cryptographic sequence SHALL NOT silently substitute for the constitutional temporal coordinate.

### T-0801-07 — No Implicit Precision

Implementation SHALL NOT infer constitutional precision or canonical representation from language/runtime defaults.

### T-0801-08 — Representation Separation

Semantic temporal meaning is established by G-0801; canonical representation and hashing remain subject to downstream decisions.

### T-0801-09 — Policy Boundary

G-0801 does not define policy-evaluation semantics.

### T-0801-10 — Receipt Boundary

G-0801 does not define receipt `executionTime` semantics.

### T-0801-11 — Fail Closed

Where temporal validity is required and the required explicit temporal coordinate is absent or invalid, execution SHALL NOT silently proceed by consulting ambient time or by assuming temporal validity.

# 19. Affected Contracts

The decision affects the semantic contract of the execution boundary by establishing the constitutional temporal coordinate:
`constitutionalTimestamp `
Any contract carrying the constitutional execution context must represent this requirement consistently.

The exact structural amendment remains subject to the already-ratified `G-0808` decision and subsequent implementation planning.

# 20. Required Follow-Up Amendments

The following follow-up work is required:

1. Update the M08 governing documentation to record Direction A as the selected temporal model.

2. Ensure the M08 implementation plan reflects the explicit temporal-input requirement.

3. Ensure `G-0807` does not introduce an alternative implicit temporal source.

4. Ensure `G-0802` treats receipt `executionTime` as a separate semantic question.

5. Ensure `G-0809` explicitly resolves canonical representation and hash-domain treatment for `constitutionalTimestamp`.

6. Ensure implementation-agent instructions prohibit ambient temporal reads inside Runtime execution.

7. Ensure tests distinguish `constitutionalTimestamp` from receipt `executionTime`.

These amendments are consequences of the decision and do not authorize implementation by themselves.

# 21. Accepted Costs and Risks

The Council accepts the following costs:

- modification of the execution-input contract;

- explicit validation of temporal input;

- additional temporal serialization requirements;

- the need to distinguish constitutional time from receipt execution time;

- additional replay fixtures covering historical temporal coordinates;

- downstream coordination with policy evaluation and hash-domain decisions.

The Council considers these costs preferable to introducing hidden environmental state or an additional temporal abstraction whose semantics would require further constitutional machinery.

# 22. Primary Advantages

The selected direction provides:

1. deterministic temporal evaluation;

2. replayability independent of wall-clock passage;

3. Runtime purity;

4. explicit constitutional provenance;

5. clear separation between temporal validity and receipt timing;

6. compatibility with the established explicit execution-context model;

7. minimal semantic complexity;

8. a clean foundation for policy temporal evaluation.

# 23. Implementation Consequence

Implementation SHALL treat the constitutional temporal coordinate as an explicit execution input.

Implementation SHALL NOT:

- read the system clock for constitutional evaluation;

- generate a substitute timestamp internally;

- silently convert `executionTime` into `constitutionalTimestamp`;

- substitute a sequence number;

- infer temporal semantics from a serialization library;

- determine unresolved temporal semantics independently.

Implementation remains subordinate to this decision and to all other applicable Council decisions.

# 25. Council Resolution

The Zyppi Constitutional Council hereby resolves:

**Zyppi constitutional temporal validity SHALL be evaluated against an explicit temporal coordinate supplied as part of the authorized execution input.**

That coordinate is designated:

`constitutionalTimestamp`

The Runtime SHALL never obtain constitutional time implicitly from its execution environment.

Temporal validity SHALL therefore be a function of explicit execution inputs and authorized constitutional state, not of the wall-clock circumstances under which the Runtime happens to execute.

Direction A is adopted.

Directions B, C, and D are rejected.
