# AMS-0205 — Create `packages/testing`

**Implements:** IT-0205
**Milestone:** M02 — Constitutional Package Structure
**Size:** XS
**Depends On:** IT-0108 ☑, AMS-0201 merged, AMS-0202 complete, AMS-0203 complete, AMS-0204 complete
**Status:** ☐ Planned

## Load

CEngS-000, CEngS-001, CEngS-002, CAW-000, CAW-004, CAW-011, and **AMS-0201**.

This mandate reuses the package-boundary pattern established by AMS-0201. Do not reproduce, redesign, or weaken that infrastructure.

## Objective

Establish `@zyppi/testing` as an independently buildable, publicly resolvable workspace package with a minimal ESM public boundary.

This task establishes package structure only. It does **not** implement test fixtures, test factories, replay harnesses, test utilities, assertions, mocks, test cases, or test behavior.

## Constitutional Package Role

Per CAW-004:

- `packages/testing` is the designated home for shared test fixtures and the replay harness.
- Testing infrastructure is shared test support, not production Runtime, Domain, Contract, Application, Edge, or infrastructure behavior.
- Future test artifacts SHALL be introduced only by the mandate that defines the behavior being tested or the testing capability being established.

### Dependency-Boundary Status

The current CAW-004 ownership/import table does **not** define a permitted-import row for `packages/testing`.

Therefore, AMS-0205 SHALL **not infer or invent** a permanent dependency graph for Testing.

For M02:

- `packages/testing/tsconfig.json` SHALL use `"references": []`.
- No internal workspace dependency SHALL be added to `package.json`.
- No cross-package source import SHALL be introduced.
- The empty reference array establishes the current scaffold baseline only; it does **not** ratify a permanent rule that Testing may never reference another package.
- When the first real shared fixture, replay harness, or cross-package testing artifact requires an internal dependency, the governing mandate SHALL identify the required relationship and reconcile it with CAW-004 before implementation.

Do not modify CAW-004’s dependency table as part of this XS scaffolding task.

## Apply the AMS-0201 Package Pattern

Create or normalize:

```text
packages/testing/
├── package.json
├── src/
│   └── index.ts
└── tsconfig.json
```

### 1. Package Manifest

`packages/testing/package.json` SHALL use the established workspace package pattern:

```json
{
  "name": "@zyppi/testing",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsc -b",
    "verify": "node ../../tools/verify-package-boundary.mjs --package=packages/testing"
  },
  "dependencies": {},
  "peerDependencies": {}
}
```

Use the repository’s canonical version. Do not introduce independent package versioning or increment the version during this scaffolding task.

The production dependency baseline is explicitly Default-Deny:

- `"dependencies"` SHALL exist and equal exactly `{}`.
- `"peerDependencies"` SHALL exist and equal exactly `{}`.
- Do not add `@zyppi/runtime`, `@zyppi/domain`, `@zyppi/contracts`, `@zyppi/shared`, or any other workspace package.
- Do not add external production or peer dependencies.
- Do not add Vitest or other test tooling to `dependencies` or `peerDependencies` merely because this package will eventually support tests.

Any future testing-only tooling dependency must be introduced by the mandate that requires it and classified according to the repository’s established dependency policy.

### 2. Public Entry Point

`packages/testing/src/index.ts` SHALL contain exactly:

```ts
export {};
```

Do not add:

- test fixtures;
- fixture factories;
- replay harnesses;
- test helpers;
- assertion helpers;
- mocks;
- stubs;
- test data;
- placeholder interfaces;
- constants;
- comments;
- temporary exports;
- test cases;
- functionality intended only to make the package appear non-empty.

Testing behavior belongs to the mandate that establishes a concrete testing requirement.

### 3. TypeScript Project References

`packages/testing/tsconfig.json` SHALL contain:

```json
{
  "references": []
}
```

Preserve the repository’s established base configuration and compiler settings where applicable.

Do not add references to:

- `runtime`;
- `domain`;
- `contracts`;
- `shared`;
- applications;
- Edge components;
- infrastructure;
- any other workspace package.

The empty reference array is the correct M02 baseline because no constitutional source currently authorizes a Testing package dependency relationship.

If the current repository project-reference graph conflicts with this requirement, stop and report the exact conflict rather than silently changing the architecture.

## Acceptance Criteria

- `packages/testing` is recognized as the `@zyppi/testing` workspace package.
- The package is independently buildable through `tsc -b`.
- The package exposes an explicit ESM public boundary through `main`, `types`, and `exports`.
- `src/index.ts` contains exactly `export {};`.
- `dependencies` and `peerDependencies` are explicitly present and exactly `{}`.
- The package has no production or peer dependencies.
- `tsconfig.json` contains an empty `references` array.
- No internal workspace project reference is introduced.
- No cross-package source import is introduced.
- No fixture, replay harness, test utility, mock, test data, or other testing behavior is introduced.
- The generic package-boundary verifier passes against `packages/testing`.
- Native Node package self-resolution succeeds through the declared public package boundary.
- The root `testing:boundary` command succeeds.
- The root `ci` script remains unchanged.
- No unrelated package, application, Edge, infrastructure, or constitutional architecture is modified.
