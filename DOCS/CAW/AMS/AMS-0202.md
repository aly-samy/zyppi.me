# AMS-0202 — Establish `@zyppi/domain` Workspace Package

**Implements:** IT-0202
**Milestone:** M02 — Constitutional Package Structure
**Size:** XS
**Depends On:** IT-0108 ☑ and AMS-0201 merged
**Status:** ☐ Planned

## Objective

Establish `packages/domain` as a minimal, independently buildable, publicly resolvable workspace package.

This mandate follows the package-boundary pattern established by AMS-0201. Do not repeat, redesign, or weaken that pattern. Apply it to `@zyppi/domain`, with the domain-specific constraint that it is a **leaf package** and therefore has no TypeScript project references or production dependencies.

## Scope

### 1. Establish the package boundary

Ensure `packages/domain/package.json` follows the manifest and public-boundary convention established by AMS-0201:

- `"name": "@zyppi/domain"`
- Repository-aligned version
- `"private": true`
- `"type": "module"`
- Top-level `"main"` pointing to `./dist/index.js`
- Top-level `"types"` pointing to `./dist/index.d.ts`
- An explicit `"exports"` map for `"."` exposing:
  - `types` → `./dist/index.d.ts`
  - `default` → `./dist/index.js`
- `"dependencies": {}`
- `"peerDependencies": {}`
- `"build": "tsc -b"`
- A package verification script reusing the shared boundary verifier created by AMS-0201

Do not add internal or external production dependencies.

### 2. Establish the minimal entry point

Create or normalize:

```
packages/domain/src/index.ts
```

Its complete contents must be:

```ts
export {};
```

Do not introduce domain entities, placeholder models, identity types, factories, constants, or speculative public APIs.

### 3. Enforce the leaf-package boundary

Ensure `packages/domain/tsconfig.json` contains:

```json
"references": []
```

`@zyppi/domain` is a leaf package under CAW-004. It may not reference or depend on any other workspace package.

Do not copy the Runtime reference pattern into Domain. Runtime’s references encode its permitted compile-time boundary; Domain’s empty reference set encodes that it may use nothing.

### 4. Reuse the shared boundary verifier

Use `tools/verify-package-boundary.mjs` created by AMS-0201.

The verifier must already support selecting a package without hardcoded Runtime-specific behavior. Invoke it for `packages/domain` using its established package-selection interface.

Do not:

- create a second boundary verifier;
- duplicate verifier logic inside `packages/domain`;
- modify the shared verifier merely to compensate for an AMS-0201 implementation defect.

If the verifier cannot validate `@zyppi/domain` without a Runtime-specific code change, stop and report that as an AMS-0201 infrastructure defect. Do not silently work around it.

### 5. Root integration

Add the corresponding root boundary-validation command following the naming convention established by AMS-0201, for example:

```json
"domain:boundary": "node tools/verify-package-boundary.mjs --package=domain"
```

Use the actual argument convention implemented by the shared verifier. Do not invent a parallel interface.

- Record the practical dependency on AMS-0201/shared boundary-verifier infrastructure if the CAW dependency notation supports it.

Do not create or update duplicate CAW-011 files.

## Explicit Non-Goals

This mandate does **not** authorize:

- Domain entities or value objects
- Identity, Evidence, Authority, Policy, Registry, or GS1 models
- Runtime behavior
- Domain services or business logic
- Public APIs beyond the empty package entry point
- Dependencies on `@zyppi/shared` or any other package
- A redesign or subdivision of the `packages/domain` boundary

CAW-003 and CAW-004 remain authoritative regarding the future domain model. Any proposal to split Domain into additional packages or redefine its ownership belongs in the appropriate constitutional decision process, not in this package-scaffolding task.

## Acceptance Criteria

All of the following must be true:

- `packages/domain` is a valid pnpm workspace package.
- The package manifest follows the AMS-0201 public-boundary convention.
- `dependencies` is exactly `{}`.
- `peerDependencies` is exactly `{}`.
- `src/index.ts` contains exactly `export {};`.
- `tsconfig.json` has `"references": []`.
- The package builds successfully with `tsc -b`.
- The shared manifest-driven boundary verifier passes for `@zyppi/domain`.
- Native package-boundary verification succeeds without Vitest aliases or source-path bypasses.
- No Runtime-specific verifier logic is duplicated.
- No domain behavior or speculative API is introduced.
- No unrelated files are modified.
