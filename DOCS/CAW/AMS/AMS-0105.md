## Objective

Configure a single, repository-wide Prettier formatting system so all supported source and configuration files use deterministic, consistent formatting through standard pnpm commands.

## Scope

Implement only the Prettier configuration and scripts required for the current monorepo.

The implementation SHALL:

1. Install the current stable Prettier release as a root development dependency.
2. Create one authoritative root-level Prettier configuration using a standard, maintainable configuration format.
3. Configure Prettier to format the repository’s relevant file types, including:

```text
*.ts
*.tsx
*.js
*.mjs
*.cjs
*.json
*.jsonc
*.yaml
*.yml
*.md
*.css
*.html
```

1. Add root package scripts that support:

```bash
pnpm format
pnpm format:check
```

Where:

- `pnpm format` applies formatting to supported repository files.
- `pnpm format:check` verifies formatting without modifying files and exits with a non-zero status when formatting violations exist.

1. Add an authoritative ignore configuration that excludes generated, dependency, build, coverage, and repository metadata directories where formatting is not appropriate.

At minimum, the ignore rules SHALL cover:

```text
node_modules/
dist/
build/
coverage/
.pnpm-store/
.git/
*.tsbuildinfo
```

1. Format the current repository after configuration so the formatting check passes from a clean checkout.
2. Preserve compatibility with the ESLint configuration created by IT-0104 without introducing duplicate or conflicting formatting enforcement.

## Out of Scope

Do **not**:

- Configure or modify ESLint rules.
- Add Prettier formatting rules to ESLint.
- Add `eslint-plugin-prettier` or use ESLint as the Prettier execution engine.
- Modify TypeScript project references.
- Configure Vitest.
- Add Git hooks, Husky, lint-staged, editor-specific automation, or pre-commit hooks.
- Add application logic, domain models, runtime logic, or production source code.
- Reorganize repository files or make unrelated cleanup changes.
- Implement CI integration. CI wiring belongs to IT-0107.

## Inputs

The repository structure and authoritative file ownership are defined by:

```text
CAW-004 — Repository Map
```

The existing root package manifest and scripts SHALL be extended without removing or weakening previously established commands.

## Constraints

- Prettier SHALL have one authoritative repository-level configuration.
- Do not create separate Prettier configurations for individual packages or applications.
- Do not introduce conflicting formatting rules across workspace packages.
- Keep the configuration minimal and based on stable Prettier defaults unless a project-specific rule is necessary.
- Do not add arbitrary stylistic preferences merely because they are available.
- Do not use ESLint to run Prettier.
- The formatting check SHALL be suitable for direct use by GitHub Actions in IT-0107.
- The implementation SHALL work from the repository root through pnpm.

## Acceptance Criteria

All of the following SHALL be true:

1. Prettier is installed as a root development dependency.
2. One authoritative root-level Prettier configuration exists.
3. One authoritative ignore configuration exists.
4. The following command formats supported repository files successfully:

```bash
pnpm format
```

1. The following command completes with zero errors after formatting:

```bash
pnpm format:check
```

1. A temporary, intentionally misformatted supported file causes:

```bash
pnpm format:check
```

to fail with a non-zero exit status.

1. After running:

```bash
pnpm format
```

the formatting check succeeds again.

1. The current TypeScript build remains valid:

```bash
pnpm exec tsc -b
```

1. If AMS-0104 has already been completed, the existing lint command continues to succeed:

```bash
pnpm lint
```

1. No package-level or application-level Prettier configurations are introduced.
2. No Git hooks, CI workflows, or unrelated tooling are added.

## Required Verification

Run the following commands from the repository root:

```bash
pnpm format
pnpm format:check
pnpm exec tsc -b
```

If AMS-0104 is complete, also run:

```bash
pnpm lint
```

Perform one negative verification by temporarily introducing invalid formatting into a supported file, confirming that:

```bash
pnpm format:check
```

fails, then restore the file by running:

```bash
pnpm format
```

The repository SHALL be left clean, correctly formatted, and passing all applicable checks.

## Definition of Done

- Prettier is installed at the repository root.
- One authoritative root-level Prettier configuration exists.
- One authoritative ignore configuration exists.
- `pnpm format` successfully formats the repository.
- `pnpm format:check` succeeds on the final repository state.
- The required negative formatting test has been performed successfully.
- `pnpm exec tsc -b` continues to succeed.
- `pnpm lint` continues to succeed when AMS-0104 is present.
- No ESLint, TypeScript, CI, Git-hook, or application logic work has been added.
- No package-level Prettier configurations exist.
- Changes are committed with a clear task-linked commit message.
