# AMS-0204 — Create `packages/shared`

**Implements:** IT-0204
**Milestone:** M02 — Constitutional Package Structure
**Size:** XS
**Depends On:** IT-0108 ☑, AMS-0201 merged, AMS-0202 complete, AMS-0203 complete
**Status:** ☐ Planned

## Load

CEngS-000, CEngS-001, CEngS-002, CAW-000, CAW-004, CAW-011, and **AMS-0201**.

This mandate deliberately reuses the package-boundary pattern established by AMS-0201. Do not reproduce, redesign, or weaken that infrastructure.

## Objective

Establish `@zyppi/shared` as an independently buildable, publicly resolvable workspace package with a minimal ESM public boundary.

This task establishes package structure only. It does **not** implement shared utilities, serialization, hashing, constants, helper functions, or other reusable behavior.

## Constitutional Package Role

Per CAW-004:

- `packages/shared` is the designated home for cross-cutting pure utilities, including future canonical serialization and hashing helpers.
- `packages/shared` is currently a leaf package and SHALL have no TypeScript project references.
- Future consumers may use `@zyppi/shared` only through its declared public boundary.

### Future Boundary Guardrail

`@zyppi/shared` is a deliberately narrow cross-cutting utility boundary. It is **not** a general-purpose `common`, `utils`, or infrastructure package.

Future additions SHALL be admitted only when they are genuinely reusable across authorized consumers and do not belong more specifically to `domain`, `contracts`, `runtime`, an application, an Edge component, or a dedicated infrastructure package.

This mandate does not authorize any implementation and does not establish a complete future utility taxonomy.

## Apply the AMS-0201 Package Pattern

Create or normalize:

```text
packages/shared/
├── package.json
├── src/
│   └── index.ts
└── tsconfig.json
```

### 1. Package Manifest

`packages/shared/package.json` SHALL use the established workspace package pattern:

```json
{
  "name": "@zyppi/shared",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsc -b",
    "verify": "node ../../tools/verify-package-boundary.mjs --package=packages/shared"
  },
  "dependencies": {},
  "peerDependencies": {}
}
```

Use the repository’s canonical version. Do not introduce independent package versioning or increment the version during this scaffolding task.

The production dependency baseline is explicitly Default-Deny:

- `"dependencies"` SHALL exist and equal exactly `{}`.
- `"peerDependencies"` SHALL exist and equal exactly `{}`.
- Do not add internal workspace dependencies.
- Do not add external production or peer dependencies.
- Do not add dependencies merely because future shared utilities may require them.

### 2. Public Entry Point

`packages/shared/src/index.ts` SHALL contain exactly:

```ts
export {};
```

Do not add:

- utility functions;
- canonical serialization;
- hashing helpers;
- constants;
- shared types;
- placeholder interfaces;
- namespaces;
- comments;
- temporary exports;
- environment access;
- framework bindings;
- infrastructure bindings;
- functionality intended only to make the package appear non-empty.

Shared behavior belongs to the mandate that introduces a concrete, constitutionally authorized need for it.

### 3. TypeScript Project References

`packages/shared/tsconfig.json` SHALL contain:

```json
{
  "references": []
}
```

Preserve the repository’s established base configuration and compiler settings where applicable.

Do not add references to:

- `domain`;
- `contracts`;
- `runtime`;
- `testing`;
- applications;
- Edge components;
- infrastructure;
- any other workspace package.

The empty reference array is intentional. It establishes `@zyppi/shared` as a zero-internal-dependency leaf package during M02.

If the current repository project-reference graph conflicts with this requirement, stop and report the exact conflict rather than silently changing the architecture.

## Shared Boundary Verification

Reuse the generic verifier established by AMS-0201:

```bash
node tools/verify-package-boundary.mjs --package=packages/shared
```

Do not:

- create a second package-boundary verifier;
- copy the verifier into `packages/shared`;
- modify the shared verifier for Shared-specific behavior;
- hardcode Shared-specific architectural rules into the verifier.

The verifier remains structural and manifest-driven. Package-specific TypeScript reference policy is governed by this mandate and the repository project graph.

## Root Integration

Add the following root script to `package.json`:

```json
"shared:boundary": "node tools/verify-package-boundary.mjs --package=packages/shared"
```

Do **not** modify the root `ci` script as part of AMS-0204.

The repository does not yet establish a canonical convention requiring every package-specific boundary command to be aggregated into the root CI command. Broader workspace boundary aggregation belongs to **IT-0208**, which is already the designated task for enforcing the CAW-004 dependency-boundary table.

`pnpm shared:boundary` remains a mandatory explicit verification step for AMS-0204.

## Acceptance Criteria

- `packages/shared` is recognized as the `@zyppi/shared` workspace package.
- The package is independently buildable through `tsc -b`.
- The package exposes an explicit ESM public boundary through `main`, `types`, and `exports`.
- `src/index.ts` contains exactly `export {};`.
- `dependencies` and `peerDependencies` are explicitly present and exactly `{}`.
- The package has no production or peer dependencies.
- `tsconfig.json` contains an empty `references` array.
- No internal workspace project reference is introduced.
- No shared utility or other implementation behavior is introduced.
- The generic package-boundary verifier passes against `packages/shared`.
- Native Node package self-resolution succeeds through the declared public package boundary.
- The root `shared:boundary` command succeeds.
- The root `ci` script remains unchanged.
- No unrelated package, application, Edge, infrastructure, or constitutional architecture is modified.
