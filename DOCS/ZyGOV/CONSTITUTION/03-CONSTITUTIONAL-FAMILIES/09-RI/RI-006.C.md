# 1. Purpose

This document defines the constitutional lifecycle of every compliant Zyppi Runtime.

It specifies:

- Runtime existence
- Runtime identity
- Runtime state transitions
- Execution Contexts
- Runtime events
- Runtime termination

It intentionally avoids implementation mechanisms such as operating systems, processes, threads, containers, hypervisors, schedulers, or programming languages.

RI-006.C defines only constitutional behavior.

---

# 2. Constitutional Principle

A Runtime is not software.

A Runtime is a temporary constitutional execution authority.

Its authority begins only after constitutional admission.

Its authority ends permanently upon constitutional termination.

A Runtime never owns constitutional truth.

It temporarily materializes constitutional truth.

---

# 3. Runtime Identity

Every Runtime SHALL possess a globally unique Runtime Identity.

Runtime Identity SHALL include:

- Runtime ID
- Runtime Version
- Constitutional Version
- Capability Manifest Hash
- Runtime Attestation
- Trust Status

Runtime Identity SHALL remain immutable throughout the Runtime Lifecycle.

Identity SHALL NOT change during execution.

---

# 4. Runtime Lifecycle

Every compliant Runtime SHALL progress through the following lifecycle.

```
Uninitialized

↓

Initializing

↓

Attested

↓

Admitted

↓

Active

↓

Degraded (optional)

↓

Suspended (optional)

↓

Active

↓

Terminating

↓

Terminated
```

No Runtime may skip constitutional lifecycle stages.

---

# 5. Constitutional Runtime States

## 5.1 Uninitialized

The Runtime possesses no constitutional authority.

No execution is permitted.

No bundle may be loaded.

No Runtime Identity exists.

---

## 5.2 Initializing

The Runtime establishes its constitutional identity.

Initialization includes:

- Identity creation
- Capability Manifest generation
- Compatibility verification
- Internal preparation

No execution authority exists.

---

## 5.3 Attested

The Runtime has successfully completed constitutional attestation.

Its identity has become trusted.

However,

execution authority has not yet been granted.

The Runtime remains idle until Admission succeeds.

---

## 5.4 Admitted

The Runtime has successfully completed Execution Admission.

Execution authority now exists.

The Runtime may begin constitutional execution.

---

## 5.5 Active

The Runtime executes constitutional operations.

During Active state it MAY:

- Resolve
- Evaluate
- Project
- Load Bundles
- Produce Receipts
- Generate Explainability
- Materialize Outputs

All execution SHALL occur inside an Execution Context.

---

## 5.6 Degraded

The Runtime remains constitutionally valid.

Certain capabilities are unavailable.

Examples include:

- Offline mode

- Reduced capabilities

- Partial projection

- Stale constitutional knowledge

Every degraded execution SHALL explicitly declare:

- degradation level

- degraded capabilities

- remaining guarantees

Security SHALL NEVER degrade.

Trust SHALL NEVER degrade.

Authorization SHALL NEVER degrade.

---

## 5.7 Suspended

Execution authority is temporarily paused.

Execution Contexts remain preserved.

No new executions begin.

Existing contexts remain recoverable.

---

## 5.8 Terminating

The Runtime is permanently relinquishing authority.

Termination SHALL include:

- Closing Execution Contexts

- Final Receipt generation

- Final Runtime Event

- Final Attestation

No new execution may begin.

---

## 5.9 Terminated

The Runtime possesses zero constitutional authority.

The Runtime SHALL NOT:

- execute

- resolve

- attest

- produce receipts

- materialize outputs

Termination is final.

Restart SHALL create an entirely new Runtime Identity.

---

# 6. Runtime State Transition Rules

State transitions SHALL be deterministic.

Transitions SHALL produce immutable Runtime Events.

Illegal transitions SHALL be rejected.

Examples:

✔ Active → Degraded

✔ Active → Suspended

✔ Suspended → Active

✔ Active → Terminating

✘ Active → Initializing

✘ Terminated → Active

✘ Terminated → Suspended

---

# 7. Execution Context

## 7.1 Definition

An Execution Context is a constitutional container for related executions.

Execution Contexts are not:

- Sessions

- Processes

- Threads

- Containers

- Connections

Execution Contexts are constitutional objects.

---

## 7.2 Purpose

Execution Contexts provide:

- execution continuity

- causal ordering

- execution budgeting

- explainability

- aggregate evidence

---

## 7.3 Execution Context Identity

Every Execution Context SHALL possess:

- Context ID

- Runtime ID

- Creation Event

- Current State

- Budget

- Aggregate Receipt

---

## 7.4 Execution Context Lifecycle

```
Created

↓

Active

↓

Suspended

↓

Resumed

↓

Closing

↓

Closed
```

Context lifecycle is independent of individual executions.

Multiple executions MAY occur within a single Execution Context.

---

# 8. Runtime Events

Every Runtime state transition SHALL generate immutable Runtime Events.

Examples include:

- Runtime Initialized

- Runtime Attested

- Runtime Admitted

- Runtime Activated

- Runtime Degraded

- Runtime Suspended

- Runtime Resumed

- Runtime Terminating

- Runtime Terminated

Events SHALL be:

- immutable

- timestamped

- attributable

- explainable

- independently verifiable

---

# 9. Aggregate Runtime Receipt

A Runtime SHALL maintain a Runtime Receipt.

This Receipt summarizes:

- Runtime Identity

- Capability Manifest

- Runtime Lifecycle

- Context Statistics

- Constitutional Events

- Final Termination Attestation

The Runtime Receipt SHALL remain independently verifiable.

It SHALL NOT require preservation of every individual execution record.

---

# 10. Runtime Authority

Runtime Authority exists only during:

- Admitted

- Active

- Degraded

- Suspended

No authority exists during:

- Uninitialized

- Initializing

- Attested

- Terminating

- Terminated

Authority SHALL NEVER survive termination.

---

# 11. Constitutional Guarantees

Every compliant Runtime SHALL guarantee:

- Immutable Runtime Identity

- Deterministic Lifecycle

- Deterministic State Transitions

- Immutable Runtime Events

- Execution Context Isolation

- Context Continuity

- Aggregate Runtime Evidence

- Zero Authority After Termination

---

# 12. Constitutional Boundaries

RI-006.C defines:

- Runtime Lifecycle

- Runtime States

- Runtime Identity

- Runtime Events

- Execution Context

RI-006.C does NOT define:

- Scheduling algorithms

- Memory management

- Threading

- Containers

- Hypervisors

- Operating systems

- Programming languages

Those belong to implementation.

---

# Constitutional Locks

## RI-LD-013 — Execution Context

Execution SHALL occur only inside constitutionally defined Execution Contexts.

Execution Contexts SHALL possess identity, lifecycle, bounded authority, and aggregate evidence.

Application sessions SHALL NOT be constitutional concepts.

---

## RI-LD-014 — Runtime Lifecycle

Every Runtime SHALL progress only through constitutionally defined Runtime States.

Illegal transitions SHALL be rejected.

Every transition SHALL generate immutable Runtime Events.

---

## RI-LD-015 — Runtime Authority

Runtime Authority SHALL exist only during constitutionally authorized lifecycle states.

Termination permanently revokes Runtime Authority.

---

## RI-LD-016 — Runtime Evidence

Runtime Lifecycle SHALL remain independently verifiable while permitting bounded evidence growth.

The Constitution defines required evidence properties, not evidence mechanisms.
