# PRJ-001 — Projection Architecture Constitution
 
Version: 1.0 (Draft for Ratification)
  
# 1. Purpose
 
PRJ-001 establishes the constitutional rules governing all Zyppi Projections.
 
A Projection is not a document, database record, digital twin, standard format, or experience.
 
A Projection is a deterministic function that transforms Reality into a consumable representation.
 
PRJ-001 ensures that:
 
 
- Reality remains canonical.
 
- Projections remain derived.
 
- Standards remain replaceable.
 
- New output formats can be added without modifying Reality.
 
- Zyppi never becomes dependent on any external standard.
 

 
PRJ-001 implements the constitutional promise:
 
 
One Reality. Infinite Projections.
 
  
# 2. Constitutional Position
 
PRJ-001 depends upon:
 
 
- ZRM
 
- RI-001 through RI-005
 
- ARM-001
 

 
PRJ-001 does not alter:
 
 
- Asset Reality
 
- Observations
 
- Relationships
 
- Profiles
 

 
PRJ-001 governs only how Reality is transformed into outputs.
  
# 3. Core Constitutional Principle
 
## CP-PRJ-001 — Projection Derivation
 
All projections SHALL be derived from Reality.
 
No projection SHALL become a source of truth.
 
Reality always precedes Projection.
  
# 4. Reality View Layer
 
## CP-PRJ-002 — Reality Views
 
Before any projection can be generated, a Reality View SHALL be computed.
 
A Reality View is a deterministic computation of an Asset Reality at a specified temporal boundary.
 
Reality Views exist to separate:
 
 
- Reality computation
 
- Projection generation
 

 
This prevents projections from embedding temporal logic.
  
## 4.1 Types of Reality Views
 
### Current View
 
Represents the latest computable state of an Asset Reality.
 
### Historical View
 
Represents the state of an Asset Reality at a specific historical sealed timestamp.
 
### Audit View
 
Represents Reality reconstructed for compliance, investigation, or governance purposes.
 
### Regulatory View
 
Represents Reality under a defined regulatory scope.
 
Future Reality View types MAY be added without modifying PRJ-001.
  
# 5. Constitutional Definition of Projection
 
## CP-PRJ-003 — Projection Definition
 
A Projection is a deterministic, policy-governed function that maps:
 
 
- A Reality View
 
- A Context Envelope
 
- Active Policies
 

 
into
 
 
- A standards-compliant or consumer-addressable output
 

 
at a specific point in time.
 
Formally:
 
Projection( RealityView, ContextEnvelope, PolicySet ) → Output
 
If all inputs remain identical, the output SHALL remain identical.
  
# 6. Projection Core
 
Every Projection SHALL contain:
 
## projection_id
 
Deterministic identifier.
 
## source_zid
 
The Asset Reality from which the projection was derived.
 
## projection_type
 
Registered Projection Specification.
 
## context_hash
 
Hash of the Context Envelope used.
 
## policy_hash
 
Hash of active policy configuration.
 
## generated_at
 
Constitutional generation timestamp.
  
# 7. Projection Derivation Rules
 
## PDR-001 — Reality Sufficiency
 
A projection SHALL only contain information derivable from:
 
 
- Asset Reality
 
- CL-04 Identities
 
- CL-11 Events
 
- Reified Relationships
 
- Context Envelope
 
- Active Policies
 

 
Projections SHALL NOT invent information.
  
## PDR-002 — Context Determinism
 
Identical inputs SHALL produce identical outputs.
 
Output variation may only result from:
 
 
- Reality changes
 
- Context changes
 
- Policy changes
 

  
## PDR-003 — Policy Interposition
 
Every projection SHALL pass through the Policy Layer before generation.
 
Policies govern:
 
 
- Visibility
 
- Redaction
 
- Jurisdiction
 
- Compliance
 
- Access
 

 
Reality itself remains unchanged.
  
## PDR-004 — Incompleteness Is Not Failure
 
If required information does not exist within Reality:
 
 
- The projection MAY be generated
 
- Missing elements SHALL be declared
 
- Missing elements SHALL NOT be fabricated
 

  
## PDR-005 — Cache Invalidation Dependency
 
Materialized projection caches are derivative artifacts.
 
Caches SHALL be invalidated when:
 
 
- Source observations change
 
- Relationships change
 
- Policy configurations change
 
- Context assumptions become invalid
 

 
Caches possess no constitutional authority.
  
## PDR-006 — Projection Purity
 
Projections SHALL only be derived from Reality Views.
 
A Projection SHALL NEVER be derived from another Projection.
 
This prevents:
 
 
- Synchronization drift
 
- Standard contamination
 
- Recursive dependency chains
 

  
# 8. Projection Identity
 
## CP-PRJ-004 — Deterministic Identity
 
Projection identity SHALL be content-addressed.
 
Projection identifiers SHALL be deterministic.
 
Equivalent projections SHALL generate identical identifiers.
 
Duplicate generation SHALL be idempotent.
  
# 9. Projection Validity
 
Projections do not possess lifecycle states.
 
Projections possess provenance.
 
Validity is computed at consumption time.
 
A Projection is valid when:
 
 
- Source Asset Reality remains resolvable
 
- Projection freshness requirements are satisfied
 
- Context assumptions remain valid
 
- Policies permit use
 

 
Validity SHALL NOT be stored as state.
  
# 10. Projection Caching
 
## CP-PRJ-005 — Materialized Projection Views
 
Projection caches are constitutionally permitted.
 
Caches are:
 
 
- Performance artifacts
 
- Recomputable
 
- Traceable
 
- Non-authoritative
 

 
A cache SHALL never replace Reality.
 
If destroyed, Reality SHALL regenerate the projection.
  
# 11. Policy Layer Interface
 
PRJ-001 defines the interface.
 
EXP-001 defines implementation.
 
The Policy Layer SHALL expose:
 
EvaluatePolicies( zid, actor, jurisdiction, intent, projection_type )
 
Result:
 
 
- included_fields
 
- excluded_fields
 
- masked_fields
 
- policy_reasoning
 
- effective_regulations
 
- expiration
 

 
PRJ-001 does not define policy content.
  
# 12. Projection Registry
 
## CP-PRJ-006 — Projection Registry
 
Every Projection Type SHALL be registered.
 
Unregistered projections SHALL NOT be generated.
 
Each registry entry SHALL declare:
 
 
- Projection Specification
 
- Freshness Model
 
- Completeness Model
 
- Policy Interface
 
- Supported Profiles
 

  
# 13. Projection Governance Rules
 
## PGR-001 — Specification Inheritance
 
All Projection Specifications inherit PRJ-001.
 
Specifications may strengthen rules.
 
Specifications SHALL NOT weaken constitutional rules.
  
## PGR-002 — Registry Governance
 
Projection Types require registration before use.
  
## PGR-003 — Standard Neutrality
 
PRJ-001 SHALL privilege no external standard.
 
GS1, DPP, Healthcare, IoT, Automotive, and future standards are equal participants.

# 15. Constitutional Boundaries
 
PRJ-001 does NOT govern:
 
 
- Asset structure
 
- Profiles
 
- Touch interactions
 
- Experience resolution
 
- SDK implementation
 
- APIs
 
- Storage mechanisms
 

 
These belong to:
 
 
- ARM-001
 
- ZT-001
 
- EXP-001
 
- SDK-001
 

 
respectively.
  
# 16. Success Test
 
If every currently known external standard disappears tomorrow and five entirely new standards emerge:
 
 
- Asset Reality SHALL remain unchanged.
 
- Observations SHALL remain unchanged.
 
- Relationships SHALL remain unchanged.
 
- Reality Views SHALL remain unchanged.
 

 
Only new Projection Specifications shall be required.
 
If this condition is satisfied, PRJ-001 is functioning correctly.
  
# 17. Constitutional Summary
 
Reality is canonical.
 
Reality is computed.
 
Reality is never synchronized.
 
Reality is projected.
 
Projections are deterministic.
 
Projections are replaceable.
 
Standards are consumers of Reality, never owners of Reality.
 
One Reality. Infinite Projections.
