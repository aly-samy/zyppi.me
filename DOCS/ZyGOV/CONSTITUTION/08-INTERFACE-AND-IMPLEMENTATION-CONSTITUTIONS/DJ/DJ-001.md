# DJ-001 — Developer Journey 001
 
## Product Authentication
 
**Document ID:** DJ-001 **Layer:** Layer 4 — Developer Platform **Status:** Canonical Developer Journey **Depends On:** DEV-ARCH-001, ZRM, CL, ARM, PRJ, SEC, POL, RI **Constitutional Authority:** None (Developer documentation only)
  
# 1. Purpose
 
This document defines the canonical first developer experience with Zyppi.
 
Its objective is not to teach the entire platform.
 
Its objective is to prove that a developer can successfully build a complete Zyppi-powered application from beginning to end while interacting with nearly every major constitutional subsystem.
 
This journey serves as the reference implementation for all future developer journeys.
 
Every future journey should feel equally simple.
  
# 2. Why Product Authentication?
 
Product Authentication is intentionally chosen because it exercises almost every core capability without overwhelming the developer.
 
It touches:
 
 
- Identity
 
- Reality
 
- Registry
 
- Runtime
 
- Policies
 
- Security
 
- QR
 
- Digital Passport
 
- Attestation
 
- Observations
 
- Developer SDK
 
- APIs
 
- Mobile
 
- Web
 

 
Yet the business problem is instantly understandable.
 
 
"Is this product authentic?"
 
 
That simplicity makes it the perfect onboarding journey.
  
# 3. Target Audience
 
This journey is designed for developers who want to:
 
 
- authenticate products
 
- build brand applications
 
- integrate websites
 
- build mobile apps
 
- integrate manufacturing systems
 
- build warranty portals
 
- create digital product passports
 

 
No previous Zyppi knowledge is assumed.
  
# 4. Success Criteria
 
At the end of this journey, the developer should be able to:
 
 
- create a Zyppi project
 
- connect to a Runtime
 
- register a product
 
- generate a Zyppi QR
 
- scan the QR
 
- resolve the product
 
- verify authenticity
 
- display the Digital Product Passport
 
- understand the execution receipt
 
- verify cryptographic trust
 
- handle failures correctly
 

 
Without understanding the internal constitutional architecture.
  
# 5. Journey Overview
 
The journey follows a realistic product lifecycle.
 
 
1. Create a Zyppi application.
 
2. Connect to a Runtime.
 
3. Register a manufacturer.
 
4. Create a product template.
 
5. Mint a product instance.
 
6. Generate a QR code.
 
7. Print and attach the QR.
 
8. Scan the QR.
 
9. Resolve the identity.
 
10. Verify authenticity.
 
11. Retrieve the Digital Product Passport.
 
12. Display trusted information.
 
13. Handle invalid or counterfeit products.
