# DJ-002 — Developer Journey 002
 
## Create a Digital Product Passport (DPP)
 
**Document ID:** DJ-002 **Layer:** Layer 4 — Developer Platform **Status:** Canonical Developer Journey **Depends On:** DJ-001, DEV-ARCH-001, ZRM, ARM, PRJ, POL, SEC, RI
  
# 1. Purpose
 
This journey teaches developers how to create, publish, and maintain a Digital Product Passport (DPP) using Zyppi.
 
Unlike DJ-001, which focuses on proving authenticity, this journey focuses on presenting rich, trusted product information throughout the product's lifecycle.
 
The developer learns how to transform a simple authenticated product into a living digital asset.
  
# 2. Business Problem
 
Customers increasingly expect transparency.
 
They want to know:
 
 
- Who manufactured this product?
 
- Where was it produced?
 
- What materials were used?
 
- Is it recyclable?
 
- Is it under warranty?
 
- Has it been serviced?
 
- Is it genuine?
 

 
A Digital Product Passport answers these questions through a trusted, structured representation of product reality.
  
# 3. Target Audience
 
This journey targets developers building:
 
 
- Brand websites
 
- Manufacturer portals
 
- Consumer mobile apps
 
- Sustainability platforms
 
- Warranty systems
 
- After-sales services
 
- Product lifecycle applications
 

  
# 4. Success Criteria
 
By completing this journey, the developer will be able to:
 
 
- define a Digital Product Passport
 
- publish passport information
 
- organize passport sections
 
- retrieve passport projections
 
- render passports on web and mobile
 
- control passport visibility through policies
 
- update passport information over time
 

  
# 5. Journey Overview
 
 
1. Create a Product Template.
 
2. Define passport metadata.
 
3. Attach structured product information.
 
4. Publish the passport.
 
5. Generate consumer access.
 
6. Retrieve the passport.
 
7. Render the passport.
 
8. Update lifecycle information.
 
9. Verify trusted provenance.
