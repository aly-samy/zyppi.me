# DJ-006 — Developer Journey 006
 
## Build a Mobile Application
 
**Document ID:** DJ-006 **Layer:** Layer 4 — Developer Platform **Status:** Canonical Developer Journey **Depends On:** DJ-001, DJ-002, DJ-003, DEV-ARCH-001, ZRM, ARM, PRJ, POL, SEC, RI
  
# 1. Purpose
 
This journey teaches mobile developers how to build native and cross-platform applications powered by Zyppi.
 
The focus is not on mobile UI design but on integrating Zyppi capabilities into applications that interact with the physical world through scanning, identity resolution, digital wallets, product verification, Digital Product Passports, offline operation, and trusted execution.
  
# 2. Business Problem
 
Modern mobile applications increasingly bridge physical and digital experiences.
 
Examples include:
 
 
- Product authentication
 
- Consumer engagement
 
- Product passports
 
- Asset management
 
- Field service
 
- Warehouse operations
 
- Retail scanning
 
- Warranty registration
 
- Equipment maintenance
 
- Government inspections
 

 
Developers need these capabilities without implementing identity systems, provenance engines, or trust infrastructure themselves.

# 7. Mobile Philosophy
 
Mobile applications are first-class Zyppi clients.
 
They should never implement constitutional logic themselves.
 
Instead, the application focuses on:
 
 
- user experience
 
- presentation
 
- interaction
 
- device capabilities
 

 
while the Runtime performs:
 
 
- identity resolution
 
- policy enforcement
 
- attestation
 
- governance
 
- execution
 
- trust

# 10. Offline Operation
 
Mobile devices frequently lose connectivity.
 
The Zyppi Mobile SDK supports:
 
 
- cached identities
 
- cached projections
 
- offline authentication (where permitted)
 
- queued operations
 
- synchronization
 
- retry handling
 
- execution receipts after reconnection
 

 
Offline behavior always follows constitutional rules defined by the Runtime.
