# 2. Constitutional Starting Point
 
The preceding dimensions established that Z-PROF is viable only if it is prevented from becoming a parallel Constitution.

It composes and binds them.

# 5. Profile Identity
 
## Decision D5-01 — Profile Identity
 
**RATIFIED**
 
The Z-PROF Profile is **not a replacement or redefinition of the ARM Profile**.
 
The existing ARM Profile remains the constitutional specialization governing an Asset Class.
 
Its fundamental question is:
 
 
**What kind of Asset Reality is this?**
 
 
Z-PROF operates at a different semantic level.
 
Its concern is:
 
 
**What does a domain require from this existing Reality?**
 
 
Therefore:
 `Asset Reality      │      ▼ ARM Profile      │      ├──────────────► Domain Composition      │      ├──────────────► Projection      │      ├──────────────► Reasoning      │      └──────────────► Other governed capabilities ` 
Z-PROF SHALL NOT broaden ARM Profile semantics merely to simplify domain composition.

## Decision D5-06 — Domain Template Card
 
**RATIFIED**
 
The **Domain Template Card (DTC)** is established as the standardized authoring and registration instrument for a domain.
 
It is **not a new constitutional semantic primitive**.
 
Its governing question is:
 
 
**What is this domain, what does it require from Zyppi, and which existing constitutional capabilities satisfy those requirements?**
 
 
The DTC SHALL prevent domain registration from becoming an uncontrolled mechanism for creating:
 
 
- new Reality primitives;
 
- new ontologies;
 
- new evidence systems;
 
- new reasoning systems;
 
- new policy systems;
 
- new execution systems;
 
- duplicate Profiles.

# 12. Epistemic Requirement Contract
 
## Decision D5-07 — Shared Epistemic Requirement Contract
 
**RATIFIED**

**Epistemic Requirement Contract**
 
 
An Epistemic Requirement Contract declares the facts, relationships, evidence classes, provenance conditions, freshness conditions, and other epistemic requirements needed by a consuming capability.

It SHALL NOT monopolize the underlying epistemic requirement concept.

# 13. Interrogation
 
## Decision D5-08 — Interrogation
 
**RATIFIED**
 
**Interrogation** is the declarative specification of what must be known to satisfy a domain requirement.
 
It answers:
 
 
**What must I know?**
 
 
It does not answer:
 
 
- How should the database be queried?
 
- Which API should be called?
 
- Which storage system should be accessed?
 
- How should evidence be retrieved?
 
- How should missing facts be fabricated?
 

 
Interrogation is therefore:
 
 
**Epistemic, not infrastructural.**
 
  
# 14. Interrogation Ownership
 
## Decision D5-09 — Separate Epistemic Requirement Ownership
 
**RATIFIED**
 
Interrogation SHALL be represented through the shared Epistemic Requirement Contract rather than being embedded exclusively inside ARM Profiles or Projection specifications.
 
Conceptually:
 `Domain Requirement        │        ▼ Epistemic Requirement Contract        │        ├──────────► Z-PROF        ├──────────► PRJ        └──────────► RSN ` 
This prevents:
 
 
- Profile overload;
 
- Projection overload;
 
- duplicated interrogation systems;
 
- infrastructure leakage.
 

  
# 15. Interrogation and Authorization
 
## Decision D5-10 — Epistemic Requirement ≠ Authorization
 
**RATIFIED**
 
Z-PROF SHALL preserve the distinction between:
 
 
**What information is required?**
 
 
and:
 
 
**Is this Subject permitted to access it?**
 
 
A domain composition may declare:
 `Requires:     Certification Evidence ` 
It SHALL NOT decide:
 `Subject X is authorized to access Certification Evidence. ` 
Authorization remains within POL/SEC jurisdiction.

 `Reality:     Evidence establishes that Event X occurred.  Interpretation:     RSN concludes that Event X satisfies Domain Condition Y. `

**Evidence establishes Reality.**
 
 
 
**Reasoning interprets established Reality.**
 
 
 
**Z-PROF composes the requirements and references necessary to support the interpretation.**
 
  
# 27. Naked Reality Gate
 
## Decision D5-20 — Epistemic Fidelity
 
**RATIFIED**
 
Z-PROF SHALL NEVER cause a representation, interpretation, judgment, or user-facing result to become stronger than the Reality and Evidence supporting it.
 
This establishes the:
 
 
**Naked Reality Gate**
 
 
The Gate does not require every interaction to produce a complete answer.
 
It requires every answer to remain bounded by what is actually established.
 
Therefore:
 `UNKNOWN      ≠ FALSE UNAVAILABLE  ≠ FALSE UNVERIFIED   ≠ VERIFIED CONFLICTING  ≠ RESOLVED INTERPRETED  ≠ OBSERVED ` 
Missing information SHALL NOT be silently completed.
